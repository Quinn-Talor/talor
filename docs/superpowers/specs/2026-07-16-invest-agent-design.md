## 0. 一页速览

- **是什么**：AI-native 投研伙伴，替散户做他做不到的严谨脑力活（读遍权威源、建因果、算估值、持续盯、对账复盘），把「好生意 × 合理价 × 耐心」这个散户唯一能赢的游戏变得可执行。
- **核心理念与 Talor 一致**：目标驱动、代码强制硬约束、prompt 软引导。
- **改动两层**：① **交互（重建为三区工作台 + 投研专属视觉，新平台 surface）** ② 执行（真相库写入闸门 + 按 agent 收窄工具，**不换 ReAct 引擎**）。领域模型 / card schema / 方法论 / 已落地硬关**保留**。
- **执行第一原则**：**AI 拿主意 / 代码守规矩** —— 守真相库闸门 + 守工具边界，**不接管流程**。
- **架构一句话**：**执行层复用 Talor（不换 ReAct + 闸门/工具/agent 复用），UI 层重建** —— invest 新增一个**三区工作台顶层 surface + 投研专属视觉**（需动平台：App.tsx surface + feature-page 机制）。执行层复用高，**UI 层是本次主要建设**。

## 1. 产品定位与非目标

### 1.1 定位

替散户完成分析师级、他没时间没能力做的工作，把结果做成**透明、可质疑、诚实标不确定**的判断；决策权永远在用户。

### 1.2 非目标（写死，代码/prompt 双重约束）

- 不荐股、不喊单。
- 不预测短期涨跌。
- 不做个性化投资建议（被要求则说明「我不是持牌顾问」）。
- 不碰交易 / 资金 / 下单。

---

## 2. 第一性原理

> **能赢的游戏 = 好生意 × 合理价 × 耐心。** 非荐股、非择时；散户赢在耐心，不在信息与速度。

1. **长期 vs 短期**：长期收益 ≈ 股息 + 盈利增长（正和）；短期 ≈ 估值波动（零和，散户系统性劣势）。→ 只玩长期正和。
2. **散户唯一优势**：耐心、无考核压力。→ 把耐心变成**可执行的纪律**（对账 / 证伪 / 双闸 / 复盘）。
3. **两大核心能力**：① 判断企业未来赚钱能力（因果链：宏观→行业空间×格局→公司份额×利润率×护城河→盈利；支点=高影响×高不确定+可证伪+有先行指标；护城河可持续性最关键）② 定价 + 安全边际（选透镜→演算图→安全边际∝不确定性；GIGO）。
4. **超额收益 = 预期差**：价值来自"市场隐含预期"与"数据揭示的真实趋势"之差；**先行指标先于价格暴露预期差** —— 这是"盯"（§5.3）与命门 `market_implied`（§8.1）的落点。

### 2.1 AI 的价值（五面，UI 必须让其可见）

| 能力       | 散户为何做不到                | 产品如何体现                                  |
| ---------- | ----------------------------- | --------------------------------------------- |
| **读得多** | 没时间读遍财报/公告/研报/行业 | 分析过程展示「读 N 源 → 提 M 条带源事实」     |
| **想得严** | 难以系统建因果、立可证伪支点  | 传导链（事实→逻辑→预期→估值）+ 卡片主角是推理 |
| **盯得住** | 盯不过来多只标的先行指标      | 待办/预警 = 「AI 替你发现你没注意的」         |
| **敢质疑** | 容易自我强化、缺对手盘        | 魔鬼代言人 / 唱空 + 可被用户怼                |
| **会进化** | 不复盘、重复同类错误          | 对账 → 归因 → 校准，越用越准                  |

## 3. 设计范围：改两层，保留其余

### 3.1 保留清单（已验证正确，不动）

| 保留项                     | 说明                                                                                                                                             |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| **领域模型 / card schema** | `CardBundle`（head + eligibility + facts + thesis + timeline）；事实三维、支点可证伪、演算图恒等式                                               |
| **业务流程**               | 案卷一生：建立 → 盯 → 对账 → 复盘                                                                                                                |
| **方法论**                 | 因果链 + 可证伪支点 + 演算图恒等式 + 三档 + 安全边际∝不确定性                                                                                    |
| **方法无关估值**           | PE/DCF/PB-ROE/DDM/NAV/PS = 同一张演算图的不同形状（声明式，叶子锚事实）                                                                          |
| **执行引擎**               | Talor 自主 ReAct（react-loop）+ prompt + 通用护栏 —— **不换**                                                                                    |
| **旧 Talor 卡结构**        | `stockCardUI.tsx` 的 DecisionSurface（①逻辑→预期 / ②预期→估值 Ladder / ③安全边际 / ④决策）+ FactRow 三维 + TimelineDrill —— **作为 UI 蓝本沿用** |
| **已落地硬关**             | 灭黑盒 / 命门必 delta / 锚同量纲 + 通用硬关（quote-verifier / path-guard / envelope / validateProfile）                                          |

### 3.2 本次改动的两层

1. **交互（重建为专属工作台）**：**新增三区工作台顶层 surface**（池子 / 活论文 / 分析过程）+ 活论文上中下（时光机 / 传导链 / 事实）+ 报问拨挑；**采用 demo 的布局与专属视觉身份**（demo = 参照规格）。**此处要动平台**（App.tsx 顶层 surface + feature-page 注册）。
2. **执行（不换引擎，加约束）**：① 真相库写入闸门（Zod + 硬关 + 冻结）② 按 agent 收窄工具白名单。

### 3.3 明确不做

不造代码编排 DAG、不换执行引擎（ReAct）、不强制 reasoning turn 输出 schema。理由：纪律的安全在写入闸门已保证；DAG 只增僵硬不增安全、逆 Talor 纹理。**注**：原「不做 invest-only chrome」随 B-ii 作废 —— invest 工作台是专属 surface + 专属视觉；但**承载它的平台机制（顶层 surface 注册 = feature-page）应做成通用**，只是 invest 的页面内容/视觉是专属的。

## 4. 执行第一原则：AI 拿主意 / 代码守规矩

> 「必须」级（有源、可证伪、算得出、命门锚定、历史不可篡改）→ **代码焊死**；「判断」级（好不好、动没动摇、为什么、该不该）→ **AI 自由**。

**「守规矩」= 守真相库闸门 + 守工具边界，不接管流程。** 机制不是「用 prompt 干预」—— prompt 只在盒子里指方向：

| 盒子的面   | 怎么实现                                                             | 硬/软 |
| ---------- | -------------------------------------------------------------------- | ----- |
| 输入       | 域 agent 走 `delegate` 隔离输入；验证型工具输入由签名/card-repo 限定 | 硬    |
| 工具白名单 | 按 agent 收窄 `allowedTools`/`agentTools`                            | 硬    |
| 输出契约   | **card-repo 写入闸门**：Zod + 硬关，不合格 → envelope、不落盘        | 硬    |
| prompt     | `agentPrompt` 软引导                                                 | 软    |

### 4.1 AI / 代码分工

| 阶段       | AI 拿主意                                | 代码守规矩（闸门/边界）                                                            |
| ---------- | ---------------------------------------- | ---------------------------------------------------------------------------------- |
| 建立       | 建因果·立支点·选透镜·三档逻辑·判断护城河 | 事实必带源+as_of · 恒等式演算 V · 命门必 delta/factor · 锚同量纲 · 过闸门才 append |
| 盯（预警） | 判断新数据动摇哪个支点 / 是否证伪 / 到点 | 取数 · 机械比对阈值 · AlertJudgment 过闸门                                         |
| 对账       | 归因：为什么偏                           | predicted vs actual 算差异 · 历史预测冻结 · Checkpoint 过闸门                      |
| 复盘       | 学到什么·哪偏了·怎么校准                 | 只读历史 · ReviewEvent 过闸门                                                      |

## 5. 交互与信息架构（定稿）

### 5.1 三区布局（左中右）

- **左 · 池子**：session 侧栏即池子，每股一份论文缩略卡（名称 + 一句话 + 状态点）；AI 报在此冒泡。
- **中 · 活论文**：主界面，案卷本身（见 5.2）。
- **右 · 分析过程**：AI 的完整分析对话（见 5.4）。

> 为什么三区：chat-中心埋论文、canvas-中心埋过程，都过度旋转。三区让**产物（论文）与过程（对话）co-present**，论文当主角、过程可见。

### 5.2 中栏 = 活论文，分上中下三段

- **上 · 时间线（时光机）** —— **是 `card.timeline` + `thesis.versions` + `facts.as_of` 的忠实投影**，不是手捏快照（对齐旧 TimelineDrill 语义）：
  - **节点按事件类型着色**：建立(空心) · 复查·校准/证伪(蓝·**版本步进**) · 复查·持有(灰·挡噪声) · 复查·异动(琥珀) · 决策(蓝方块) · 复盘。
  - **逻辑版本脊梁 + 轨迹条**：显示 validity 序列 / 版本 v1→v2 / 仓位 —— 一眼看出"逻辑慢变(少数版本)、复查多次"。
  - **拖动/点击任一节点 = 回放该时刻完整论文**（facts as_of ≤ T + thesis 生效版本 + 估值/结论）**+ 展开该事件详情**：复查→对账表(predicted 冻结 vs 实际 vs outcome + 归因) / 决策→trade@price·仓位·双闸 / 校准→版本 diff。
  - 历史 = 只读·冻结；现在 = 可编辑（活·可拨）。数据基础见 §8.2。
- **中 · 传导链（逻辑最新）** —— `事实 → 逻辑 → 预期 → 估值 → 决策`，对齐旧 Talor DecisionSurface：
  - **① 逻辑 → 预期**：每个命门 `锚(事实)@as_of —「逻辑」→ 估(熊/中/牛三档)`；兑现度 / 确信 / 实测背离。
  - **② 预期 → 估值（恒等式 Ladder）**：逐步 `LHS 算式(代入真实值·命门标蓝) = 中间量 / V`，命门/计算标签，熊/牛带；方法无关。
  - **③ 安全边际**：价格尺（现价 vs 熊/中/买点，绿色买入区）。
  - **④ 决策**：verdict + 仓位 + 理由 + 非荐股。
  - **拨（what-if）**：点命门（如净利率）就地重算，变化顺 净利→EPS→V 传导、**在数据上体现**；仅「现在」可拨（历史冻结）。
- **下 · 事实（全展开 + 变化趋势）** —— 对齐旧 FactRow，每条**三维**：
  - **值** + **变化**（趋势 ↑↓→ + trend_note「22%→19%」+ 换手等）+ **结构**（note + 质量 健康/混合/恶化 + 成分信号 pill）。
  - 先行·验证主力 置顶，再 公司/行业/宏观；带源 @as_of、过时标红；先行/排雷 role pill。

### 5.3 AI 定节奏（事件驱动）

建立一次 → 后台盯 → 到点/异动才叫你（报）。**数据变化先传到先行指标，再传到命门**，体现在传导链与时间线上。（自动调度 = v2。）

### 5.4 右栏 = 分析过程（AI 价值可见）

一条对话线程，承载 AI 全过程：建立（读 N 源→提事实→立支点→诚实标"最担心"）/ 追问 / 挑刺（唱空 + 回应）/ 主动报（预警/对账/复盘）。这是"读得多/想得严/盯得住/敢质疑/会进化"看得见的地方。composer 支持 问/拨/挑，每类轮次带一句"价值提示"。

### 5.5 交互语法 + 三视图联动

- **报**（AI 主动）/ **问**（点元素或输入）/ **拨**（改假设即重算）/ **挑**（唱空）。
- **三视图 = 一条时间轴的三个投影**：时间线（轴）↔ 活论文（状态）↔ 分析过程（事件流），点任一同步其余（点支柱 → 定位对话轮次；时间线点 ↔ 预警/对账轮次）。

## 6. 执行架构

### 6.1 决策：阶段=槽、域=agent、代码守闸门

| 类别                                                                     | 具体                                                                                                             | 载体                |
| ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------- | ------------------- |
| **是 agent**（AgentProfile，走 react-loop）                              | ① 主 agent（对话脑：建立编排/追问/挑刺）② 宏观/行业/标的 specialist（域，`delegate` fan-out，主 agent 汇总落卡） | Talor 现成运行时    |

### 6.3 验证型工具（阶段槽）定义

## 8. 数据与契约

### 8.1 保留 card schema（沿用现有 `invest.ts`）

- **资格赛（eligibility）**：好生意先过资格赛 —— 正和（非零和赌局）/ 能力圈 / 红灯排雷 + 护城河（type + durability）；不过则决策面红灯、不建仓。
- **Fact（三维）**：`series[]` append-only 观测；每个 `FactObservation` = `value` + `change`（`trend: up/down/flat` + `trend_note` + `momentum`/`yoy`/`percentile`/`turnover_*`）+ `structure`（`note` + `quality: healthy/mixed/deteriorating` + `components[]{name,signal}`）+ `as_of` + `source` + `tier`；`role: 先行/同步/滞后/排雷`。
- **传导链**：`ValuationAssumption`（`anchor{fact,as_of}` + `forecast{mode:delta/factor/absolute, bear/base/bull, horizon}` + `logic` ⟺ 命门 + `falsify_if` + `market_implied`（预期差对照）+ `step{order,op,out}`）；`Valuation`（`method` + `assumptions[]` + `V{bear,base,bull}` + `margin_of_safety`）。Ladder 由 `computeValuationTrace` 逐步折叠得出。
- **Checkpoint**（predicted/actual/deviation/outcome/attribution）、**ReviewEvent**、**ThesisSnapshot**（v/at/scope/claim）。

### 8.2 事件溯源：`card(T)` 可由时间线重建（时光机的数据基础）

> **更正（读真实 schema 后）：时光机零 schema 改动 —— card 本就是事件溯源的。**

- **事实**：`FactObservation.as_of` + `series` append-only → 快照 = 所有 as_of ≤ T 的观测。
- **逻辑**：`thesis.versions[]` **已带 `v` / `at` / `scope`(建立/校准/重写) / `ref_checkpoint`** —— 逻辑本就冻结版本化。→ 快照 = T 时刻生效的那一版（整卡快照粒度，无需 per-元素版本化）。
- **事件**：`timeline[]`(复查/决策/复盘) 各带 `at`；复查 `validity`=校准/证伪 才 `spawned_v`(逻辑脊梁步进)，强化/持有不换版。
- **对账**：`Checkpoint.checks[].predicted_value`(建卡锚定·冻结) vs `actual_value`(facts 到期最新)。
- 结论：facts(as_of) + thesis(versions.at) + timeline(at) 已构成完整事件溯源，`card(T)` 可重建 —— UI 时间轴按此投影即可（§5.2）。六不变量中"事实只增不改 / 复查锚出身不回溯"已在代码层保证冻结。

### 8.3 四个产出物 Zod schema（写入闸门校验）

`CardBundle`（建立）/ `AlertJudgment{pivot_id,severity,理由}`（预警）/ `Checkpoint{delta,attribution}`（对账）/ `ReviewEvent{bias,校准量}`（复盘）。

### 8.4 不变量

- **V-flow**：当前活算 / 历史冻结 —— 落盘不可篡改（否则对账/时光机失真）。改前必读。
- **三道硬关**：灭黑盒 / 命门必 delta / 锚同量纲，扩为每产出物校验。
- **事实 append-only**；**逻辑版本 append-only**。

## 11. 开放问题（实施前定）

1. **域 agent 整合**：主 agent 如何消费宏观/行业/标的 specialist 的结构化输出 —— 三者输出 schema 需对齐。
2. **compute\_\* 与 MCP 取数边界**：哪些走 invest_lib 纯函数，哪些走数值 MCP。
3. **验证型工具形态**：预警/对账/复盘 三个独立工具，还是一个带 `phase` 参数（倾向独立，schema/白名单各异）。
4. **护城河可证伪化（建议纳入 MVP）**：`good_business.moat` 目前只有 `{type, durability枚举}`，缺像命门那样的 `falsify_if` + 先行指标；护城河可持续性是最关键判断却结构最薄 —— 小改，给 moat 加"何以侵蚀 + 先行指标"。
5. **因果传导结构化（留 v-next）**：`assumption` 只 `anchor` 单一事实 + `logic` 文本，表达不了 宏观→行业→公司 多级传导、也不能"上游数据变自动传到公司命门"；要自动传导需 假设↔上游事实/假设 的显式依赖边。MVP 单股靠 anchor+logic 够用。

> 已关闭：早期"逻辑版本化落库形态" —— 真实 schema 里 `thesis.versions` 已是整卡快照版本化（§8.2），无需新增。

## 12. 验收标准

- [ ] 单股「建立 → 盯 → 对账 → 复盘」闭环端到端跑通。
- [ ] **写入闸门生效**：构造不合格产出（缺源事实 / 算不出的估值 / 篡改历史预测）→ envelope 拒绝、不进 card-repo（触发+不触发两测）。
- [ ] **时光机可重建**：任一历史时间点重建的 card = 当时落盘的快照（facts as_of ≤ T + 该版逻辑）；历史只读、现在可拨。
- [ ] **传导重算**：拨命门 → 净利/EPS/V 沿恒等式一致重算（纯 compute，不经 LLM）。
- [ ] **工具白名单收窄**：域 specialist 调不到建卡工具。
- [ ] **对话层不污染真相库**：追问/挑刺自由文本不写 card-repo。
- [ ] 三道硬关 + V-flow 冻结 + 逻辑版本 append-only 在新路径生效。
- [ ] react-loop / registry / delegate **未被改动**（diff 为证）。
