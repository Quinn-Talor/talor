## 0. 读法

| 标记   | 含义                                                                       | 可变性                                 |
| ------ | -------------------------------------------------------------------------- | -------------------------------------- |
| 【事】 | 事实：外部世界已经发生、可观测的值（公告、数据、行情、政策原文、成交回报） | 只追加；修订用新记录加 `supersedes`    |
| 【线】 | 线索：未经官方来源证实的信息（媒体报道、快讯、传闻）                       | 只追加；可被证实或证伪                 |
| 【判】 | 判断：LLM 或用户写下的主张、假设、规则、解释、动作                         | 只能出新版本或新记录                   |
| 【算】 | 计算结果：代码由事实、线索和判断推出                                       | 不接受调用方传入；需要留历史时冻结快照 |
| 【系】 | 系统字段：id、版本号、时间戳                                               | 只由服务端生成                         |

写入者：`接入`（信息接入服务）/ `抽取`（接入服务内的 LLM 抽取调用）/ `LLM:<角色>` / `用户` / `代码`。

文中数字凡标"示意"者，只用于说明机制，不构成对任何标的的判断。

## 1. 一句话模型

> **逻辑是一个以估值公式表达、可计算、可证伪的价值主张**：资产在未来一个时间窗内的价值，由宏观、行业、公司变量通过确定的公式算出；变量要么绑定事实，要么是带区间和证伪条件的假设。事件到达后变成某个变量的变化，公式重算得出价值变化，据此判定事件是在验证、强化、动摇还是证伪这个逻辑。决策依据逻辑状态行动，复盘评估公式里的假设和决策本身。

```
             ┌──────────────────────────────── 逻辑周期 [t₀, T] ─────────────────────────────────┐
             │                                                                                   │
  事实 ──绑定──▶ 宏观变量 ─┐                                                                       │
  （观测）      行业变量 ─┼─▶ 公司变量 ─▶ 财务变量（只能由公式推出）─▶ 估值层（按标的画像选方法，默认 PE）│
  假设 ──取值──▶          │         公式（经营模型，行业模板）                 V_T、V₀、预期回报        │
  情景开关 ─────▶          │                                                   主张：回报不等式          │
             │            ▲               ▲                     ▲                    ▲               │
             │        宏观事件         行业事件            财报、公司公告              价格            │
             │            └── 每个事件变成某个变量的变化 → 重算 → ΔV → 验证 / 强化 / 动摇 / 证伪 ──┘    │
             └─────────────────┬─────────────────────────────────────────────────────────────────┘
                               ▼
             逻辑状态（经营 × 定价 × 生命周期）──▶ 决策 ──▶ 成交 ──▶ 决策评估、逻辑周期复盘、教训 ──▶ 下一个逻辑周期
```

## 2. 目标、范围与决策

### 2.1 目标

1. **逻辑可计算**：逻辑就是一个估值公式加上对每个变量的绑定，任何时候都能重算出价值。
2. **事件可量化**：任何事件都落到某个变量的变化上，能算出它让价值变了多少。
3. **逻辑状态由代码推出**，决策与卖出由逻辑状态推出。
4. **每个环节是否闭合都能由代码检查**（§17）。

## 3. 设计原则

| #   | 原则                                                                                                                              |
| --- | --------------------------------------------------------------------------------------------------------------------------------- |
| P1  | **逻辑是中心，公式是逻辑的骨架**：因果关系就是公式本身，不另建文字因果图                                                          |
| P2  | **事前由 LLM 定规则，事中由代码执行规则，事后由数据评估规则**：假设路径、证伪规则、情景开关的状态与映射、收敛条件都在立逻辑时写下 |
| P3  | **一切影响都要进入公式**：事件变成变量变化；无法量化的变成门槛加成；不允许只有文字的影响                                          |
| P4  | **作用由逻辑结构决定，不由信息频率决定**                                                                                          |
| P5  | **价格只作用于定价**；价格异动只触发找原因                                                                                        |
| P6  | **线索不是事实**：可以触发保守响应，不能作为事实绑定或对账值                                                                      |
| P7  | **冲突取保守**：默认紧急等级由代码给出；作用由代码计算；LLM 只能升级不能降级                                                      |
| P8  | **三类数据分离、引用只向下、身份由服务端分配**：工具 schema 中不出现【算】【系】字段                                              |
| P9  | **不确定就保守**：依据不足体现为更宽的区间、更高的门槛、更小的仓位                                                                |
| P10 | **公式必须安全**：公式由受限表达式语言书写，用语法树解释执行，禁止 `eval`                                                         |
| P11 | **宁少而硬**：每条规则都在命令处理器里强制                                                                                        |
| P12 | **先外部视角，再内部视角**：关键增长与利润率假设须说明参照类（同类公司在类似规模或阶段的表现），中档明显好于参照类须给理由        |

## 4. 什么是逻辑

### 4.1 定义

> **逻辑（Thesis）是一个以估值公式表达、可计算、可证伪的价值主张。** 在时间窗 [t₀, T] 内，资产价值由宏观、行业、公司变量通过确定的公式算出；每个变量要么绑定事实（已观测的数据），要么是假设（对其未来路径的预测，带区间、理由和证伪条件）；主张是：按此公式，在基准和熊市情景下，从现在持有到 T 的回报满足要求。

```
V_T(s) = F( 事实变量(t),  假设变量(s, 各期),  情景开关(s) )          s ∈ {熊, 中, 牛}
coe    = rf + β × ERP
V₀(s)  = ( V_T(s) + D(s) ) ÷ (1 + coe)^τ

主张：  ( V_T(中) + D ) ÷ P ≥ (1 + h)^τ        且        ( V_T(熊) + D ) ÷ P ≥ 1 − L
```

其中 h 为有效回报门槛（§8.4），L 为最大可承受亏损，τ 为距兑现的年数，D 为期间分红。

### 4.2 组成

| 组成         | 是什么                                                         | 谁给出                                      |
| ------------ | -------------------------------------------------------------- | ------------------------------------------- |
| **变量**     | 公式中的每一个量，分五层，按期展开                             | 模板 + LLM 扩展                             |
| **公式**     | 派生变量 = 其他变量的确定表达式，附机制说明                    | 模板 + LLM 扩展，代码校验                   |
| **事实绑定** | 叶子变量 ← 观测；事件到达后自动更新                            | 代码                                        |
| **假设**     | 叶子变量在未来各期的预测：锚、路径、理由、驱动、证伪条件       | LLM                                         |
| **观点引用** | 宏观、行业层变量引用全局观点的指定版本（§4.12），偏离须理由    | 观点由宏观、行业研究维护；引用由代码解析    |
| **情景开关** | 不可量化的外部条件（如政策状态），每个状态映射到明确的假设调整 | LLM，代码校验                               |
| **情景**     | 熊、中、牛三套连贯的取值组合                                   | LLM 定义，代码校验                          |
| **主张**     | 回报不等式、预期差、收敛条件                                   | 不等式与预期差由代码计算；收敛条件由 LLM 写 |

### 4.3 五个必要属性

| 属性     | 含义                                           |
| -------- | ---------------------------------------------- |
| 有资产   | 针对一只具体的股票                             |
| 有时间窗 | 立论时点 t₀、检查点、兑现期 T、收敛窗口        |
| 可计算   | 由公式算出 V，任何时刻可重算、可追溯每一步     |
| 有定价   | V_T、V₀、预期回报、市场隐含值、预期差          |
| 可证伪   | 假设有路径区间和证伪规则，情景开关有"破坏"状态 |

### 4.4 哪些不是逻辑

| 概念 | 与逻辑的关系                                   |
| ---- | ---------------------------------------------- |
| 事实 | 绑定到变量，作为当前值和锚；也是假设的对账值   |
| 事件 | 变成变量的变化，作用于逻辑                     |
| 资格 | 逻辑的准入条件（公司值不值得研究），在逻辑之外 |
| 决策 | 依据逻辑状态采取的行动，在逻辑之外             |

### 4.5 变量

**五层**

| 层   | 含义                         | 例子                                                           |
| ---- | ---------------------------- | -------------------------------------------------------------- |
| 宏观 | 经济、政策、利率             | 乘用车总销量、社零增速、10 年期国债收益率、LPR、购置税减免状态 |
| 行业 | 行业规模、结构、价格、成本   | 新能源渗透率、行业均价变化、碳酸锂价格变化、高端白酒批价       |
| 公司 | 公司经营的驱动               | 份额、单价、单位成本、费用率、海外销量、贷款增速、净息差       |
| 财务 | 财务结果，**只能由公式推出** | 营收、毛利率、净利、扣非 EPS、ROE、BVPS、自由现金流、DPS       |
| 估值 | 把财务结果变成价值           | PE_T、PB_T、coe、V_T、V₀                                       |

**财务层与通用模板**：财务层指由经营模型推出的结果量（营收、净利、扣非 EPS、ROE、BVPS、自由现金流、DPS 等）。毛利率、费用率在行业经营模板中由公式推出；通用模板没有经营细分时，营收增速、毛利率、费用率作为**公司层驱动变量**登记为假设，净利、EPS 仍须由公式推出（`RESULT_ASSUMED` 只对后者生效）。

**六种类型**

| 类型     | 含义                                       | 取值来源                                                              |
| -------- | ------------------------------------------ | --------------------------------------------------------------------- |
| 事实变量 | 当前可观测的量                             | 事实绑定，自动更新                                                    |
| 假设变量 | 未来值需要预测的量                         | 假设的各期路径（熊、中、牛）                                          |
| 观点变量 | 宏观、行业层的共享预测                     | 引用全局观点（§4.12）的指定版本；逻辑内不能直接改，偏离须走"观点偏离" |
| 派生变量 | 由公式计算的量                             | 公式                                                                  |
| 情景开关 | 离散的外部条件                             | 当前状态取自事实或复查结论；各情景取值由情景定义                      |
| 常量     | 有出处的固定值（如法定税率、电池成本占比） | 引用事实或法规                                                        |
| 参数     | 规则参数中的全局值（如 ERP）               | RuleParams                                                            |

**变量的时间维度与口径**

- 每个变量声明频率（月 / 季 / 年）与口径（单期、年初至今累计、TTM、期末存量），按期展开（如 2026Q3、2026 年）；公式按期计算，检查点和兑现期都对应某一期。
- 流量（销量、营收、净利）按期求和；比率（毛利率、费用率、净息差）由同口径的分子、分母重算，**不对比率取平均**；存量（股本、BVPS、贷款余额）取期末值。
- 年度变量的季度检查点按"年初至今累计"登记路径点（每个季度一组累计的熊、中、牛），与同口径观测对账；月度观测用于先行验证，不直接对账年度路径。
- 观测进入对账前按变量口径换算（单期 → 累计、累计 → TTM 等）；换算所需的期次缺失时不对账，记为"口径缺失"并生成补取事实任务；口径无法换算时拒绝绑定（`PERIOD_BASIS_MISMATCH`）。
- **股本**：存在未转股可转债、已披露的增发预案或在实施的股权激励时，股本必须登记为假设（按转股价、增发规模给出路径），不能作为事实（`DILUTION_UNMODELED`）。

### 4.6 公式与表达式语言

- 每个派生变量有一条公式，附**机制说明**（为什么这个关系成立）。
- 公式用受限表达式语言书写，代码解析为语法树后解释执行，**不使用 `eval`**。允许：数字、变量引用（可带期偏移，如 `revenue[-1]` 表示上一期）、`+ − × ÷ ^`、`min`、`max`、`clamp`、`sum`（对分部求和）、`sw(开关, {状态: 值, …})`（按情景开关取值）。不允许其他函数、字符串、自定义函数、递归。
- 代码检查：语法、引用存在、无环、**量纲一致**。单位由基本单位（元、辆、股、吨、年）与数量级前缀（万 = 10⁴、亿 = 10⁸）组成：量纲按基本单位比较，前缀在求值时换算，所以"万辆 × 万元/辆 = 亿元"成立，"亿元 + 辆"拒绝（`UNIT_MISMATCH`）；同一表达式中同量纲、不同前缀相加（如"亿元 + 元"）换算到规范单位后求值，并给出警告（`UNIT_SCALE_MIXED`，不拒绝）。单位为 `%` 的变量进入公式时自动按比率处理。

### 4.7 假设

| 要素       | 说明                                                                                                                                                       |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 主体与指标 | 绑定指标定义，用于对账和路由                                                                                                                               |
| 锚         | 立论时该指标的最新观测，由服务端解析（新变量无历史时，必须引用可比对象的事实，并标记"无本体历史"）                                                         |
| 预测方式   | 相对锚的增量或倍数；**关键假设不允许直接给绝对值**                                                                                                         |
| 各期路径   | 每个检查点一组熊、中、牛；兑现期 T 为终点                                                                                                                  |
| 理由       | 为什么取这些值，必须引用至少一条事实或事件                                                                                                                 |
| 参照类     | 关键假设中的增长与利润率假设须说明参照类：同类公司在类似规模或阶段的历史表现（文字必填，数据可选）；中档明显好于参照类须给理由（`KEY_NO_REFERENCE_CLASS`） |
| 驱动       | 该假设依赖的外部变量或情景开关（宏观、行业层），附机制说明；**关键假设至少一个外部驱动**                                                                   |
| 证伪规则   | `{指标, 比较符, 阈值, 连续期数}`；关键假设必填                                                                                                             |
| 角色       | 估值输入（在 V 的计算路径上）/ 先行验证（不进入 V，用于提前验证上游假设）；由代码按可达性判定                                                              |
| 关键       | 由敏感度计算（§8.8），LLM 可追加，不能删除                                                                                                                 |

**估值层倍数不是本节意义上的假设**：PE_T、PB_T 等倍数的取值、区间与约束由 §5.5 规定，不适用"关键假设不允许绝对值""至少一个外部驱动""证伪规则必填"三条；倍数参与敏感度排序（§8.8）用于展示，关键假设只从宏观、行业、公司层与长期增长段的假设中选出。长期增长段（g₁、n、分红率）适用本节全部要素（§5.5）。

### 4.8 情景开关与情景

**情景开关**表示无法用连续数值表达的外部条件。

| 要素             | 说明                                              |
| ---------------- | ------------------------------------------------- |
| 主题             | 关联主题词典，事件通过主题路由到开关              |
| 状态             | 例如购置税减免：延续 / 减半 / 取消                |
| 每个状态的严重度 | 基准 / 削弱 / 破坏，立逻辑时写下                  |
| 每个状态的映射   | 该状态下哪些假设如何调整，例如"减半：渗透率 −3pp" |
| 当前状态         | 立论时由事实确定；之后由复查中的情景切换改变      |
| 紧急等级         | L3 或 L4                                          |

**情景**是三套连贯的取值组合：

| 情景     | 定义规则                                                                                                                                             |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 中       | 所有假设取中档；情景开关取当前状态                                                                                                                   |
| 熊       | LLM 定义一条连贯的下行叙事（例如"价格战加剧"），指定哪些假设取熊档、哪些开关取哪个状态；**必须包含敏感度前 k 个假设中的至少 k − 1 个**，防止避重就轻 |
| 牛       | LLM 定义一条连贯的上行叙事，规则同上                                                                                                                 |
| 压力测试 | 所有关键假设同时取熊档、所有开关取最坏状态；**只展示，不进入买点**                                                                                   |

### 4.9 主张、预期差与收敛条件

- **回报不等式**（§4.1），由代码计算是否成立。
- **预期差**：对每个关键假设，代码反解"让 V₀(中) 等于现价"的值（市场隐含值，按当前倍数与我方倍数各算一次，§8.5），给出我方中档与隐含值的差距；LLM 解释市场为什么看错。
- **收敛条件**：什么会让市场重新定价（例如"年报显示份额 ≥ 29.5% 且毛利率 ≥ 19%"），关联哪些假设，以及时间窗。

### 4.12 观点（全局共享的宏观、行业预测）

宏观、行业层的预测（乘用车总量、新能源渗透率、行业均价、碳酸锂价格、LPR 等）对覆盖相关标的的所有逻辑应当一致，否则组合层会出现自相矛盾的世界观，例如两张整车卡假设不同的行业总量、份额之和超过合理范围。

| 要素   | 说明                                                                                                                                             |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 观点   | 一组宏观或行业变量的假设与路径（熊、中、牛）、驱动与证伪规则，结构同 §4.7；按主题或行业组织，版本化                                              |
| 维护   | macro-research、industry-research 起草，PM 提交（`propose_view`）；适用 §4.10 中关于假设的完备性规则                                             |
| 引用   | 逻辑中的宏观、行业变量引用某个观点版本（变量类型"观点变量"）；观点出新版本时，引用它的逻辑在下一次 L1 重算中更新取值，价值变动桥列为"观点更新"   |
| 偏离   | 逻辑可以对观点变量给出不同的路径，须给理由并标记"观点偏离"，计入门槛加成 `p_view_override`；同一观点变量在多张卡上的偏离方向相反时，闭合检查告警 |
| 情景   | 观点给出熊、中、牛三档；逻辑的情景定义引用观点的档位                                                                                             |
| 一致性 | 同一行业、同一口径下各卡的份额中档之和不超过 1（`VIEW_SHARE_INCONSISTENT`，提交时检查）                                                          |

首期只要求：行业经营模板中的宏观、行业变量若已有观点，必须引用（`VIEW_REFERENCE_REQUIRED`）；没有观点时可以在逻辑内假设，并自动生成"建立观点"任务。

## 5. 标的画像与估值方法

### 5.1 默认方法：前瞻 PE

```
V_T = 扣非 EPS_T × PE_T
```

- **EPS 口径**：扣非 EPS，由经营模型推导到兑现期 T 所在的会计年度；不允许直接假设 EPS。
- 大多数标的走这条路径；例外由标的画像自动判定。

### 5.2 标的画像（AssetProfile）

| 维度     | 取值                                                                 | 判定                                                                                               |
| -------- | -------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 行业组   | 金融-银行 / 金融-券商 / 金融-保险 / 周期 / 资源 / 地产 / 公用 / 一般 | 代码：行业分类 → 行业组映射                                                                        |
| 盈利状态 | 稳定盈利 / 亏损或微利 / 周期性                                       | 代码：最近 TTM 扣非净利 ≤ 0 为亏损；近 5 年扣非净利变异系数 > `cyclical_cv` 或属周期行业组为周期性 |
| 分红特征 | 高股息 / 一般                                                        | 代码：近 3 年平均分红率 ≥ 50% 且股息率 ≥ 4%                                                        |
| 业务结构 | 单一 / 多元                                                          | 代码：最大分部收入占比 < 60% 且分部数 ≥ 2 为多元                                                   |
| 价值来源 | 经营 / 资产重估 / 管线                                               | LLM 判断，代码校验与其他维度不冲突                                                                 |

画像随资格评估一起生成，并在年报披露后的复查中重新评估。

### 5.3 画像 → 方法

| 画像（按顺序匹配）               | 主方法              | 交叉验证                                                 | 本期   |
| -------------------------------- | ------------------- | -------------------------------------------------------- | ------ |
| 金融-保险                        | P/EV                | PB                                                       | 不支持 |
| 金融-银行、金融-券商             | PB-ROE              | 股息率                                                   | 支持   |
| 资源、地产，或价值来源为资产重估 | NAV                 | PB                                                       | 不支持 |
| 价值来源为管线                   | rNPV                | PS                                                       | 不支持 |
| 多元                             | SOTP                | PE                                                       | 不支持 |
| 亏损或微利                       | PS + 盈利路径       | 远期 PE 折现                                             | 支持   |
| 周期性                           | 正常化盈利 PE       | PB                                                       | 支持   |
| 其余（稳定盈利）                 | **前瞻 PE（默认）** | 高股息用股息率；模板含现金流模块时用 DCF；其余用反向 DCF | 支持   |

不支持的画像可以建卡、做资格评估、接收信息，但不能提交逻辑（`METHOD_NOT_SUPPORTED`）。

### 5.4 方法估值模板

| 方法                 | 估值层公式                                                                                                                                                                                                     |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 前瞻 PE              | `V_T = EPS_T × PE_T`                                                                                                                                                                                           |
| PB-ROE               | `BVPS_T = BVPS₀ + Σ EPS − Σ DPS`；`V_T = BVPS_T × PB_T`；推出值 `PB = (ROE_T − g) ÷ (coe − g)`                                                                                                                 |
| 正常化盈利 PE        | `EPS_norm = BVPS_T × ROE_norm`（ROE_norm 为近一个完整周期的平均 ROE，假设）；`V_T = EPS_norm × PE_norm`                                                                                                        |
| PS + 盈利路径        | `V_T = 营收_T × PS_T`；必须同时给出盈利路径：盈亏平衡期、目标净利率、目标年份 Y；交叉验证 `V_T' = 营收_Y × 目标净利率 ÷ N × PE_Y ÷ (1 + coe)^(Y − T)`                                                          |
| DCF（交叉验证）      | `企业价值 = Σ FCFF ÷ (1 + WACC)^t + 终值`；`股权价值 = 企业价值 − 净负债`；FCFF 由经营模型的利润、折旧、资本开支、营运资本推出（需模板含现金流模块）                                                           |
| 反向 DCF（交叉验证） | 已知现价 P、当前扣非 EPS₀、退出倍数 PE_exit（取 §5.5 中档）、贴现率 coe、年数 n（= 长期增长段 n）：`g_implied = (P × (1 + coe)^n ÷ (EPS₀ × PE_exit))^(1/n) − 1`；与长期增长段 g₁ 比较（复用现有 `reverseDcf`） |
| 股息率（交叉验证）   | `V = DPS_{T+1} ÷ (coe − g)`，g ≤ `g_terminal_cap`                                                                                                                                                              |

### 5.5 倍数来源

PE_T、PB_T、PE_norm、PS_T 都按以下规则确定。倍数是估值层的取值，不是 §4.7 意义上的假设；但决定合理倍数的长期增长段是假设。

| 步骤                 | 规则                                                                                                                                                                                                                                                                                                |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ① 相对历史分位定区间 | 倍数序列用**相对基准**口径：标的扣非 TTM PE ÷ 基准 PE（`relative_multiple_benchmark`，默认沪深300；行业组为金融、周期时用所属行业指数），取 `multiple_history_years` 年分位，再乘以当前基准 PE 折回绝对值。熊 = `p_bear` 分位，牛 = `p_bull` 分位，中档候选区间为 `[p_center_lo, p_center_hi]` 分位 |
| ② 基本面推出值       | PE：两段式 `PE_T = Σ_{i=1..n} 分红率₁ × x^i + 分红率₂ × (1 + g₁)^n × (1 + g₂) ÷ ((coe − g₂) × (1 + coe)^n)`，其中 `x = (1 + g₁) ÷ (1 + coe)`；PB：`(ROE − g) ÷ (coe − g)`。`g₂ ≤ g_terminal_cap`，`coe − g₂ ≥ min_spread`。按 g₁ 的熊、中、牛分别得到推出值 J(熊)、J(中)、J(牛)                     |
| ③ 中档               | 中档须落在 ① 的中档候选区间内，或落在 J(中) × (1 ± `justified_tolerance`) 内，否则拒绝（`MULTIPLE_CENTER_OUT_OF_RANGE`）。只满足其中一个时（中档在 ① 之外，或与 J(中) 相差超过容差），须说明市场为何偏离历史或基本面，并计入 `p_multiple`                                                           |
| ④ 熊档               | 熊档取 ① 的 `p_bear` 分位与 J(熊) 的**较低者**：估值体系结构性下移（行业增速换挡、政策压制）时，熊档不会停留在过去的高分位                                                                                                                                                                          |
| ⑤ 增速换挡           | 标的画像变化，或 g₁(中) 与近 `multiple_history_years` 年实际扣非 EPS 复合增速相差超过 `regime_shift_gap` 时，① 只作参照：中档以 J(中) 为准（须在 ③ 的容差内），并计入历史不足加成                                                                                                                   |
| ⑥ 同业分位参照       | 同行业可比公司的同口径倍数分位，只报告                                                                                                                                                                                                                                                              |
| 历史不足             | 不足 `multiple_min_years` 年：熊 = 中 × `fallback_bear_factor`，门槛计入历史不足加成                                                                                                                                                                                                                |

**长期增长段是可证伪的假设**：g₁、n、分红率₁ 登记为估值层假设，结构同 §4.7——锚为近 3 至 5 年实际扣非 EPS（或营收）复合增速；先行验证变量至少一个（资本开支强度、产能投放、研发投入、新业务收入占比等）；证伪规则作用于滚动复合增速（例如"滚动 3 年扣非 EPS 复合增速 < g₁(熊) 连续 2 期"）。它们进入推出值，再经 ③④ 进入倍数与 V，因此参与敏感度排序，可以成为关键假设。回报来源为成长或拐点时，长期增长段的锚、先行验证和证伪规则必填（`LONG_GROWTH_UNFALSIFIABLE`）。

推出值使 coe 进入倍数：利率下行时推出的合理倍数上升，经 ③④ 影响中档与熊档，这是宏观作用于估值的定量通道。

### 5.6 PEG 检查

回报来源类型为成长或拐点时：`PEG = PE_T(中) ÷ (g₁(中) × 100)`，增速取长期增长段 g₁（§5.5），不用当前 EPS 到 EPS_T 的短期增速——时间窗不足一年时年化会严重失真。超过 `peg_max` 时须给出理由（`PEG_TOO_HIGH`）。

### 5.7 交叉验证与分歧

```
分歧 = |V_T(中, 主方法) − V_T(中, 交叉验证)| ÷ V_T(中, 主方法)
```

超过 `cross_check_divergence`：必须说明原因，并把 `p_divergence × 分歧` 计入有效门槛。

交叉验证方法为反向 DCF 时按增速比较：`分歧 = g₁(中) − g_implied`（百分点）。超过 `implied_growth_gap` 时同样须说明原因，并按 `p_divergence × 分歧 ÷ g₁(中)` 计入门槛。

### 5.8 行业经营模板（首批骨架）

| 行业 | 方法                      | 核心变量与公式骨架                                                                                                      | 必需的情景开关主题                     |
| ---- | ------------------------- | ----------------------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| 整车 | PE                        | 乘用车总量 × 渗透率 × 份额 + 海外 → 销量；行业均价 × 传导 → 单价；原材料 → 单位成本；毛利率、费用率 → 净利              | 购置税政策、价格战、海外贸易壁垒       |
| 白酒 | PE                        | 销量 × 吨价（直销占比、出厂价）→ 营收；毛利率、税金率、费用率 → 净利；批价与渠道库存为先行验证                          | 消费税改革、渠道价格体系               |
| 家电 | PE                        | 内销量（地产竣工、以旧换新）+ 外销量（汇率）→ 销量；均价、原材料（铜铝钢）→ 毛利率；费用率 → 净利                       | 以旧换新补贴、原材料价格、出口与汇率   |
| 银行 | PB-ROE                    | 贷款增速 → 生息资产；净息差（LPR、存款利率）→ 利息收入；非息收入；成本收入比；信用成本 → 净利 → ROE、BVPS；分红率 → DPS | LPR 与存款利率调整、地产风险、地方债务 |
| 煤炭 | 正常化 PE，交叉验证股息率 | 产量 × 煤价（长协与市场价比例）→ 营收；单位成本 → 利润；周期平均 ROE → 正常化 EPS；分红率 → DPS                         | 产能与安监政策、进口煤、长协价格机制   |
| 通用 | PE                        | 营收增速、毛利率、费用率（公司层驱动变量，§4.5）→ 净利                                                                  | 无                                     |

首期模板不含现金流模块（折旧、资本开支、营运资本），稳定盈利标的的交叉验证用反向 DCF；需要 DCF 交叉验证的模板须先补齐现金流模块。

模板版本化，修改需用户批准（结构性教训可以提议修改）。

### 5.9 方法切换

标的画像变化（例如由亏转盈、进入或离开周期底部）导致主方法变化时，必须提交新的逻辑版本，版本类型为**重写**。

## 6. 逻辑周期

### 6.1 时点

| 时点     | 含义                                           |
| -------- | ---------------------------------------------- |
| t₀       | 逻辑版本冻结时间；只能使用 t₀ 之前已披露的事实 |
| 检查点   | 假设路径上的每一期，按**预计披露日**到期       |
| T        | 估值输入假设的最后一个检查点                   |
| 收敛窗口 | 预计市场重新定价的时间段                       |
| τ        | 当前到 T 预计披露日的年数                      |

### 6.2 生命周期

| 状态       | 判定                                                                   |
| ---------- | ---------------------------------------------------------------------- |
| active     | 当前版本，T 的观测尚未披露                                             |
| due        | T 的观测已披露，尚未终验复查；超过 `due_grace_days` 后定价状态为"过期" |
| superseded | 被校准、重写或滚动出的新版本接替                                       |
| completed  | 终验时经营成立且定价已收敛，或用户选择结束                             |
| falsified  | 经营证伪且选择不重写                                                   |
| abandoned  | 放弃，不再覆盖该逻辑                                                   |

### 6.3 版本类型（代码比较新旧版本判定）

| 类型 | 判定                                                                                                                                                                                                                                                                  |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 新立 | 卡上没有 active 逻辑                                                                                                                                                                                                                                                  |
| 校准 | 变量、公式、开关结构、估值方法不变；只改了假设路径数值、开关映射数值、倍数中档、收敛条件；**不得放宽证伪规则**（放宽阈值或延长连续期数判为重写，并计一次动摇）；每个逻辑周期最多 `max_calibrations_per_cycle` 次，超出时拒绝（`CALIBRATION_BUDGET_EXCEEDED`），须重写 |
| 重写 | 变量或公式增删改，开关增删或状态集改变，或估值方法改变                                                                                                                                                                                                                |
| 滚动 | 结构不变；T 后移，并给出新的路径                                                                                                                                                                                                                                      |

**逻辑周期**：从一次新立或重写开始，到下一次重写、完成、证伪或放弃为止；其间的校准与滚动属于同一周期。

### 6.4 到期处理

终验复查必须给出结局：完成、滚动（附滚动草案）、重写（附重写草案）、证伪（可附重写草案，或放弃）。连续 `max_rolls_without_convergence` 次未收敛的滚动后不能再滚动（`ROLL_LIMIT_REACHED`）。

## 7. 事件对逻辑的作用

### 7.1 事件 → 变量变化

| 事件                           | 转换                                                                                                           | 谁转换                     |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------- | -------------------------- |
| 财报、月度数据、行业数据、行情 | 事实变量更新；与假设路径和派生变量路径的检查点对账                                                             | 代码，即时                 |
| 利率、汇率等宏观数据           | 事实变量更新                                                                                                   | 代码，即时                 |
| 政策、行业动态、公司公告       | 三选一：**事实更新**（政策参数变了，录入为观测）/ **情景切换**（开关状态变了）/ **假设修订**（随复查出新版本） | LLM 在复查中提出，代码重算 |
| 无法量化的定性信息             | 登记为**未量化风险**，计入门槛加成，直到被量化、证伪或解除                                                     | LLM 登记，代码计入         |
| 与逻辑无关                     | 无关，须给出理由                                                                                               | LLM                        |

### 7.2 作用的判定（代码）

| 作用     | 判定                                                                                                  |
| -------- | ----------------------------------------------------------------------------------------------------- |
| 验证     | 观测落在该期路径的熊、牛区间内（兑现或容差）；或转换后 \|ΔV(中)\| < `effect_threshold`                |
| 强化     | 观测越过牛档（有利方向）；或转换后 ΔV(中) ≥ +`effect_threshold`                                       |
| 动摇     | 观测低于熊档；先行指标未达；转换后 ΔV(中) ≤ −`effect_threshold`；开关切到"削弱"状态；登记为未量化风险 |
| 证伪     | 触发证伪规则；开关切到"破坏"状态                                                                      |
| 只改定价 | 只有估值层的事实变量变化（价格、rf、β、倍数历史）                                                     |

ΔV(中) 指该事件转换后，V_T(中) 相对变化前的变化率，其他变量保持不变。LLM 可以把作用判得更严重，不能更轻（`EFFECT_CONFLICTS_COMPUTED`）。

**同时满足多条时的优先级**：不利作用优先于有利作用；不利作用中取最严重者（证伪 > 动摇）；有利作用中取较弱者（验证 > 强化，即观测在区间内而 ΔV 越过阈值时判为验证）。与 P7"冲突取保守"一致。

### 7.3 各类事件通常作用于哪些变量

| 事件           | 通常作用于                                             |
| -------------- | ------------------------------------------------------ |
| 宏观数据       | 宏观层变量；coe（rf）；市场状态                        |
| 政策           | 情景开关；政策参数类事实变量                           |
| 行业数据       | 行业层变量（渗透率、均价、原材料）及其路径             |
| 财报、业绩预告 | 公司层假设的对账；财务派生变量的对账；锚与事实变量更新 |
| 公司公告       | 公司层假设、情景开关；否决级事件                       |
| 价格           | 只作用于定价                                           |
| 新闻快讯       | 对应部分，但作为线索                                   |

### 7.4 紧急等级与作用

| 维度           | 回答的问题                                 | 由谁决定                                  | 何时                         |
| -------------- | ------------------------------------------ | ----------------------------------------- | ---------------------------- |
| 紧急等级 L0–L4 | 多快处理、处理前是否冻结买入               | 代码，按信息命中了逻辑的哪一部分（§10.7） | 信息入库时                   |
| 作用           | 对逻辑是验证、强化、动摇、证伪还是只改定价 | 代码，按对账与 ΔV                         | 数值即时；定性在复查中转换后 |

### 7.5 状态推导

**假设状态**

| 状态 | 条件                                                                                       |
| ---- | ------------------------------------------------------------------------------------------ |
| 证伪 | 触发证伪规则；或其驱动开关处于"破坏"状态                                                   |
| 存疑 | 最近一次对账低于熊档；先行验证连续 `leading_miss_limit` 次未达；或其驱动开关处于"削弱"状态 |
| 成立 | 其余                                                                                       |

**派生偏离**：财务派生变量（如毛利率、净利）的实际值低于该期派生熊档，即使各假设都在区间内，也记为派生偏离。

**事实漂移**：自版本创建以来，由事实更新和情景切换（不含价格、rf、时间推移）累计造成的 V_T(中) 变化 ≤ −`drift_threshold`。

**逻辑漂移**：自本逻辑周期起点（新立或重写的版本）以来，由假设修订（校准、滚动）累计造成的 V_T(中) 下修 ≥ `revision_drift_threshold`（按价值变动桥的"假设修订"分项累计，上修不抵扣下修）。逻辑漂移使经营状态为存疑；累计下修达到 2 × `revision_drift_threshold` 时，下一次复查只能重写、证伪结案或放弃。

**经营状态**

| 经营状态 | 条件                                                                                                                       |
| -------- | -------------------------------------------------------------------------------------------------------------------------- |
| 证伪     | 任一关键假设证伪                                                                                                           |
| 存疑     | 任一假设存疑；任一派生偏离；任一开关处于"削弱"；存在 L3 级的未量化风险；事实漂移；逻辑漂移；或盈利质量检查触发 L3（§10.8） |
| 成立     | 其余                                                                                                                       |

**存疑的处理**：本次复查必须提交校准或重写草案，或对该假设使用一次豁免（理由为噪声或外生；同一假设连续豁免不超过 `excuse_budget` 次；连续两次同向偏离不可豁免）。证伪时必须重写、证伪结案或放弃。

### 7.6 价值变动桥

每次复查和每次 L1 重算都生成价值变动桥：从上一个定价快照到这一个，逐项列出

| 分项       | 例子                     |
| ---------- | ------------------------ |
| 事实更新   | 份额实际值替换锚         |
| 情景切换   | 购置税减免：延续 → 减半  |
| 假设修订   | 新版本调整了渗透率路径   |
| 未量化风险 | 门槛加成变化对买点的影响 |
| 时间推移   | τ 变小，V₀ 上升          |
| 价格、rf   | 定价层变化               |

各分项对 V_T(中)、V₀(中)、买点价的贡献由代码按顺序替换计算，合计等于总变化。

### 7.7 确信度

| 复查中的作用汇总       | 分值变化                           |
| ---------------------- | ---------------------------------- |
| 有强化，且无动摇、证伪 | +1                                 |
| 只有验证               | +0.5                               |
| 有动摇（含已豁免）     | −1                                 |
| 有证伪                 | 置为 −2；重写或新立的版本从 0 开始 |

≥ 2 为高，0 到 2 为中，< 0 为低。滚动和校准继承分值。

## 8. 定价计算

### 8.1 V_T

按情景分别求值：三个情景的变量取值代入公式，按期计算到 T，得到 V_T(熊)、V_T(中)、V_T(牛) 和每一步的中间值（计算过程完整保留，供界面展示）。

### 8.2 期间分红与 V₀

```
D    = 现在到 T 的预期分红（由经营模型的 DPS 推出；模型没有 DPS 时取最近一期每股分红事实 × 期间年数）
τ    = 现在到 T 预计披露日的年数（不小于 0）
V₀   = (V_T + D) ÷ (1 + coe)^τ
```

### 8.3 预期回报

```
R(中) = (V_T(中) + D) ÷ P − 1      年化：(1 + R)^(1/τ) − 1（τ < 0.25 时按 0.25 处理）
R(熊) = (V_T(熊) + D) ÷ P − 1
```

**情景加权期望（只展示，待模拟验证，§21 D11）**：LLM 在情景定义中给出熊、中、牛的主观概率（和为 1）；代码计算 `E[R] = Σ p(s) × R(s)` 与偏度 `(R(牛) − R(中)) ÷ (R(中) − R(熊))`，在定价快照中展示，首期不进入买点与状态判定。

### 8.4 有效门槛与买点

```
h = hurdle_base
  + premium_grade[资格等级]
  + p_width       × (V_T(牛) − V_T(熊)) ÷ V_T(中)
  + p_unverified  × 尚未有任何对账的关键假设数 ÷ 关键假设总数
  + p_time        × τ
  + p_divergence  × 交叉验证分歧（超过阈值时）
  + p_multiple    × （倍数与推出值冲突时）
  + Σ 未量化风险加成
  + 历史不足加成
  上限 hurdle_cap

买点价 = min( (V_T(中) + D) ÷ (1 + h)^τ ,  (V_T(熊) + D) ÷ (1 − max_loss) )
```

不确定性在门槛（区间宽度、未验证、时间）、熊市约束、建议仓位（§9.3）与确信度（§7.7）中多处计入，可能过度保守。各分项的初始参数须在公式引擎完成后用历史回放检验再定（§21 D10）：检验"按模板构建的合理逻辑在回放期内进入低估的时间占比"以及随后的超额收益。

### 8.5 市场隐含值与预期差

对每个关键假设：其他变量取中档，在该变量合理区间内用二分法求解，使 V₀(中) = P。分别在两种倍数下求解：**我方倍数**（PE_T 中档）与**当前倍数**（当前扣非 TTM PE 保持到 T）。两者都展示；预期差与 `NO_VARIANT_GAP` 以当前倍数下的隐含值判定，避免预期差由倍数的选择制造出来。

```
隐含值 x*：V₀(中)(x*) = P
预期差 = (我方中档 − x*) ÷ |x*|，按方向修正
```

不单调或无解时记为"无法反解"。

### 8.6 回报来源分解

| 方法      | 分解                                                                                    |
| --------- | --------------------------------------------------------------------------------------- |
| PE        | EPS 增长 = EPS_T ÷ 当前扣非 EPS − 1；PE 变化 = PE_T(中) ÷ 当前扣非 PE − 1；分红 = D ÷ P |
| PB-ROE    | BVPS 增长；PB 变化；分红                                                                |
| 正常化 PE | 正常化 EPS 相对当前 EPS 的变化；倍数变化；分红                                          |
| PS        | 营收增长；PS 变化                                                                       |

回报来源类型为成长或拐点、但倍数贡献超过盈利贡献时，标记"回报来源不一致"，须说明。

### 8.7 定价状态

| 状态   | 条件（按顺序）                                                                                |
| ------ | --------------------------------------------------------------------------------------------- |
| 过期   | 生命周期为 due 且超过宽限期                                                                   |
| 已收敛 | \|P − V₀(中)\| ÷ V₀(中) ≤ `convergence_tol`，且所有关键假设在最近一个已到期检查点为验证或强化 |
| 高估   | P ≥ V₀(牛)                                                                                    |
| 低估   | P ≤ 买点价                                                                                    |
| 合理   | 其余                                                                                          |

### 8.8 敏感度与关键假设

对每个假设和倍数：其他取中档，该变量分别取熊档和牛档，计算 V_T(中) 的变化幅度，按幅度排序（龙卷风图）。前 `key_top_k` 个自动成为关键假设；LLM 可以追加，不能删除。

### 8.9 利率与股权成本

```
rf  = 10 年期国债收益率最新观测
β   = 对沪深300 的周收益回归（beta_window_weeks），Blume 调整 0.67β + 0.33；数据不足取 1
coe = rf + β × ERP
```

rf 的新观测对所有逻辑触发"只改定价"的重算；倍数的基本面推出值随 coe 变化，用于校验与冲突检查。

### 8.10 路径带宽下限

```
sigma = 该指标最近 band_history_periods 期相邻变化的标准差
每个检查点最小带宽 = band_min_k × sigma × sqrt(该检查点距锚的期数)
历史不足 band_min_history 期：跳过下限，计入历史不足加成
```

## 9. 决策

### 9.1 逻辑状态 → 允许的动作

| 经营 | 定价   | 无持仓                       | 有持仓                     |
| ---- | ------ | ---------------------------- | -------------------------- |
| 成立 | 低估   | 建、等待                     | 加、持有、减               |
| 成立 | 合理   | 等待（建需 override）        | 持有、减（加需 override）  |
| 成立 | 高估   | 等待                         | 减、清、持有（需理由）     |
| 成立 | 已收敛 | 等待；须完成或滚动逻辑       | 减、清；持有需同时滚动     |
| 任意 | 过期   | 等待                         | 持有、减、清；须做到期处理 |
| 存疑 | 任意   | 等待                         | 持有、减、清               |
| 证伪 | 任意   | 等待；须重写、证伪结案或放弃 | 减、清                     |

不在允许范围内的动作被拒绝（`ACTION_NOT_ALLOWED`）。override 只能放宽定价维度；无持仓时可选"停止覆盖"，卡归档。

### 9.2 建仓、加仓闸门

| 闸            | 条件                                                                           | 可否 override    |
| ------------- | ------------------------------------------------------------------------------ | ---------------- |
| G0 冻结       | 没有 pending 的 L3、L4 影响评估；没有未完成的不利方向异动核查任务（§10.10）    | 否               |
| G1 经营       | 经营状态 = 成立                                                                | 否               |
| G2 时效       | 依据复查之后没有新的 L2 及以上影响评估；复查距今 ≤ `review_max_age_days`       | 否               |
| G3 资格       | 最新资格评估通过且未过期                                                       | 否               |
| G4 市场       | 建：市场 gate ≠ 否决；加：∉ {否决, 节流}                                       | 否决不可；节流可 |
| G5 定价       | 定价状态 = 低估                                                                | 可               |
| G6 生命周期   | 逻辑为 active                                                                  | 否               |
| G7 单票上限   | 目标仓位 ≤ `single_cap`                                                        | 否               |
| G8 组合预算   | 目标仓位 ≤ 剩余卫星仓预算、行业预算                                            | 可               |
| G9 主题集中度 | 加入后，任一情景开关主题的持仓合计 ≤ `topic_cap`                               | 可               |
| G10 披露静默  | 不在关键检查点预计披露日前 `pre_disclosure_blackout_days` 个交易日内（建、加） | 可               |

**市场 gate**：否决 = 存在 pending 的 L4，或回看期内有否决级事件，或市场状态 systemic = extreme，或资格不通过；节流 = 市场状态 direction = 恶化；警告 = systemic = warning；其余通行。

### 9.3 建议仓位

```
depth       = clamp((买点价 − P) ÷ 买点价, 0, 1)
depth_scale = clamp(0.5 + depth ÷ depth_full, 0.5, 1)
uncertainty = clamp(u_width × (V_T(牛) − V_T(熊)) ÷ V_T(中) + u_unverified × 未验证比例 + u_time × τ + 历史不足加成, 0, 1)

建议仓位 = min( single_cap,
               single_loss_budget ÷ max(|R(熊)|, 0.05),
               risk_budget × conv_factor[确信度] × depth_scale × (1 − uncertainty),
               20 日日均成交额 × liquidity_ratio ÷ 卫星仓资金,
               剩余卫星仓预算, 剩余行业预算, 剩余主题预算 )
```

`single_loss_budget ÷ |R(熊)|` 使单票在熊市情景下对卫星仓造成的损失不超过 `single_loss_budget`：熊市跌幅越大，仓位越小（参数待模拟验证，§21 D12）。

### 9.4 卖出信号

| 信号      | 触发                 | 建议                                                                     |
| --------- | -------------------- | ------------------------------------------------------------------------ |
| S0 否决   | 存在 pending 的 L4   | 清仓或减仓，置顶                                                         |
| S1 证伪   | 经营证伪             | 清仓                                                                     |
| S2 高估   | 定价高估             | 减至 × `take_profit_keep`；P ≥ V₀(牛) × (1 + `take_profit_extra`) 时清仓 |
| S3 完成   | 经营成立且定价已收敛 | 减仓或清仓，或滚动                                                       |
| S4 未收敛 | 收敛窗口结束仍未收敛 | 复查；滚动达上限时减半                                                   |
| S5 过期   | 定价过期             | 复查；超过宽限期两倍时减半                                               |
| S6 超限   | 单票、行业、主题超限 | 减回上限                                                                 |

卖出信号只是建议，执行需要复查、决策和用户录入成交。跌停、停牌时卖出通常无法成交：信号保持置顶，并在可成交日重新提示；录入成交时校验成交价在当日涨跌停区间内（`TRADE_PRICE_OUT_OF_RANGE`）。

### 9.5 override

只有用户能发起；冷静期 `override_cooldown_hours`；生效前不得录入关联成交；冷静期内可取消；进入复盘统计。

权威性分三档：official（官方）可生成事实与事件；commercial（白名单商业数据商）只生成观测，tier 为 T2，不生成事件；media 只生成线索。

### 10.2 调度与回补

接入服务在应用运行时（含托盘常驻）按信息源配置和交易日历调度；每个信息源维护游标，启动时回补最多 `backfill_max_days` 天；失败指数退避，连续失败标记不健康并提示。

### 10.3 处理流水线

```
拉取 → 原始信息
  → ① 去重：URL、内容哈希、24 小时内近似哈希 → 归入已有信息条目或新建
  → ② 粗筛（代码）：标的名称、代码、简称，行业名称，主题关键词与别名，宏观指标名的字典匹配；未命中只存档
  → ③ 抽取（LLM，仅命中条目）：摘要、事件类型、涉及的公司、行业、主题、候选数值
  → ④ 合并标签：代码匹配 ∪ 抽取结果（抽取只能增加）
  → ⑤ 生成事实：official → 事件与观测；commercial（白名单）→ 观测（T2）；media → 只作线索
  → ⑥ 即时对账与重算（代码，§10.8）
  → ⑦ 路由与分级（§10.7）→ 影响评估
  → ⑧ 响应：冻结、通知、任务、收件箱
```

### 10.4 抽取约束

抽取没有写入工具；输出须通过 schema 校验；只能增加标签；不能给出等级或作用；候选数值只有来源为 official 或白名单 commercial、且通过观测校验后才成为事实。

### 10.5 线索证实

线索路由为 L3、L4 时同时生成核实任务；找到官方来源则关联并按官方条目处理；核实为不实则线索与相关影响评估标为 refuted 并解除冻结；时限内未核实则保持冻结，并在 `rumor_freeze_days` 个交易日后生成用户裁决任务：继续冻结、登记为未量化风险后解除冻结（门槛加成按线索等级），或判为无关（须理由）。冻结不会无限期地静默持续。

### 10.6 成本控制

只有粗筛命中的条目调用抽取；每日上限 `llm_daily_extractions`；超出按优先级排队（否决类关键词 > 持有中卡的开关主题 > 其他），积压时提示。

### 10.7 路由索引与紧急等级

**索引**由所有卡的 active 逻辑构建：

| 键                             | 来自                                   |
| ------------------------------ | -------------------------------------- |
| `topic:<key>`                  | 情景开关的主题；假设驱动中声明的主题   |

| `pricing:<代码>`               | 价格、估值序列                         |
| `macro:cn_10y`、`macro:regime` | 所有逻辑                               |

**默认紧急等级（取最高）**

| 命中                                                              | 等级                                                |
| ----------------------------------------------------------------- | --------------------------------------------------- |
| 本公司否决级事件                                                  | L4                                                  |

| 即时对账：任一假设证伪，或关键假设动摇，或派生偏离                | L3                                                  |

### 10.8 即时对账与重算

观测入库后代码立即：

1. 更新所有绑定该指标的事实变量；
2. 对所有以该指标为假设、且报告期等于某检查点的 active 逻辑，生成**假设对账**；
3. 对财务派生变量的观测（如毛利率、净利），按该期派生熊、中、牛值生成**派生对账**；
4. 定期报告到达时运行**盈利质量检查**（`quality_checks`，复用资格评估的红灯定义与 `RED_FLAG_THRESHOLDS`）：经营现金流 ÷ 净利、应收与存货增速相对营收增速、商誉 ÷ 净资产、有息负债 ÷ 总资产、存贷双高，结果按 §10.7 定级；
5. 用最近若干期序列判定证伪规则；
6. 重算受影响逻辑的定价快照与价值变动桥；
7. 按 §10.7 定等级：验证、强化只记录（L1）；动摇、证伪、派生偏离生成影响评估。

复查汇总这些对账，不重新判定已由代码判定的数值作用。

### 10.9 响应与时限

| 等级 | 自动动作                                                       | 冻结           | 通知                                         | 时限     |
| ---- | -------------------------------------------------------------- | -------------- | -------------------------------------------- | -------- |
| L1   | 重算定价快照、价值变动桥、卖出信号；信号触发时生成"待决策"提示 | —              | —                                            | 自动     |
| L2   | 加入待处理队列                                                 | —              | 收件箱                                       | `sla.L2` |
| L3   | 加入待处理队列；线索生成核实任务                               | 冻结建仓、加仓 | 收件箱角标（可配置桌面通知）                 | `sla.L3` |
| L4   | 加入待处理队列；市场 gate 否决；卖出建议；线索生成核实任务     | 冻结建仓、加仓 | **桌面通知**；应用未运行期间产生的启动后补发 | `sla.L4` |

冻结不随时间自动解除；卖出不自动执行。

### 10.10 价格监控

盘中按 `price_poll_interval` 轮询覆盖卡现价：穿越买点价、V₀(牛)、止盈线时 L1 重算并提示；每个交易日盘后对所有 active 逻辑做一次 L1 重算（τ 变小，V₀ 和买点价随之变化）；异动（单日相对沪深300 偏离超过 `anomaly_daily`，或 10 日累计超过 `anomaly_10d`）生成异动核查任务；不利方向的异动在核查完成前冻结建仓、加仓（§9.2 G0）；找到原因则作为信息条目进入流水线，超过 `sla.anomaly` 仍未解释则记为未解释异动，并升级为 L3 影响评估。

### 10.11 收件箱

按优先级：逾期与即将到期的 L4、L3；待决策提示；到期待终验的逻辑；未完成任务；需要写教训的评估与复盘；待批准的规则参数和模板修改；信息源健康告警与抽取积压。

## 11. 复查

### 11.1 触发

| 触发     | 条件                                                   |
| -------- | ------------------------------------------------------ |
| 信息     | 存在 pending 的 L2 至 L4 影响评估                      |
| 检查点   | 某检查点观测已披露（即时对账已完成，复查做汇总与决策） |
| 到期     | 逻辑为 due                                             |
| 时间兜底 | 持有中超过 30 天、观察中超过 90 天未复查               |
| 决策     | 价格信号或卖出建议出现，需要新鲜复查才能决策           |

### 11.2 预览与提交

1. `preview_review`：代码汇总截止前的全部待处理影响评估、已完成的对账、到期检查点、假设与开关状态、经营状态、定价快照、价值变动桥、定价状态、允许的动作、需确认的教训，返回预览令牌。
2. PM 为每条定性影响评估提出**转换**（事实更新、情景切换、假设修订、未量化风险、无关），可以再次预览，查看转换后的 ΔV 和作用。
3. short-thesis 对预览结果提交挑战，覆盖全部 L3、L4 条目。
4. `commit_review`：提交转换、豁免、升级、教训确认、挑战引用与裁决、决策，以及需要时的新版本草案或到期结局；代码校验后在一个事务内写入。

预览后又出现 L2 及以上影响评估时，令牌失效（`REVIEW_PREVIEW_STALE`）。

### 11.3 提交时的校验

| 错误码                                             | 规则                                                                                        |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `REVIEW_ITEMS_UNRESOLVED`                          | 每条被消费的 L2 至 L4 影响评估都有转换                                                      |
| `EFFECT_CONVERSION_REQUIRED`                       | 定性条目必须转换为变量变化、未量化风险或无关之一                                            |
| `EFFECT_REASON_REQUIRED`                           | L3、L4 条目转换为"无关"，或转换后作用为验证时，必须对照开关状态定义或证伪规则说明为何未触发 |
| `EFFECT_CONFLICTS_COMPUTED`                        | 升级只能更严                                                                                |
| `SWITCH_STATE_UNKNOWN`                             | 情景切换的目标状态必须是该开关事前定义的状态                                                |
| `CHALLENGE_ITEMS_NOT_COVERED`                      | 挑战覆盖全部 L3、L4 条目                                                                    |
| `LESSONS_NOT_ACKNOWLEDGED`                         | 适用的生效教训全部确认                                                                      |
| `REVIEW_REVISION_REQUIRED`                         | 经营存疑且未豁免时须附校准或重写草案；证伪时须附重写草案或选择证伪结案、放弃                |
| `DUE_OUTCOME_REQUIRED`                             | 逻辑为 due 时必须给出到期结局                                                               |
| `VERSION_TYPE_MISMATCH`                            | 草案的版本类型与结局不符                                                                    |
| `ROLL_LIMIT_REACHED`                               | 连续未收敛滚动达到上限                                                                      |
| `ACTION_NOT_ALLOWED`、`GATE_FROZEN`、`GATE_FAILED` | 决策动作与闸门                                                                              |

### 11.4 版本处理与决策

新版本草案在同一事务内走一遍 §4.10 全部完备性检查，代码判定版本类型，旧版本标为 superseded；到期结局为完成、证伪、放弃时，同时生成逻辑周期复盘的计算部分。每次复查以且仅以一个决策结束。

## 12. 复盘与学习

### 12.1 决策评估

| 决策         | 评估                                                                                                     |
| ------------ | -------------------------------------------------------------------------------------------------------- |
| 建、加、持有 | 期限内实际持仓收益（Modified Dietz）对比同期基准（沪深300 全收益）与所属行业指数（`industry_benchmark`） |
| 等待         | 若在决策时按建议仓位买入的假想收益，即机会成本                                                           |
| 减、清       | 卖出部分在期限内的收益：下跌为避免的损失，上涨为错过的收益                                               |

**原因归类（代码）**：

| 情况                                                               | 归类                                          |
| ------------------------------------------------------------------ | --------------------------------------------- |
| 相关信息发布早于依据复查的截止时间，但入库晚于截止时间             | 信息遗漏-接入                                 |
| 相关信息在依据复查中转换为"无关"或作用为验证，之后被证明动摇或证伪 | 信息遗漏-判断                                 |
| 窗口内某假设或开关被动摇、证伪，且它在事前登记的逻辑中             | 已知风险兑现（记录具体变量与 ΔV）             |
| 窗口内的重大 ΔV 来自兜底路由的信息（逻辑中没有对应变量或开关）     | 变量遗漏                                      |
| 窗口内关键假设验证或强化，但价格未向 V₀(中) 收敛，且超额为负       | 经营兑现未收敛                                |
| 相对行业指数超额 ≥ 0，但相对沪深300 超额为负                       | 行业拖累（选股正确，行业判断失误或行业 beta） |
| 以上都没有                                                         | 市场波动                                      |

**必须写教训**：3 个月、12 个月、周期结束评估中，超额低于 −`lesson_excess_threshold`、归类为任一遗漏、或使用过 override。1 个月评估只展示。

### 12.2 逻辑周期复盘

每个逻辑版本结束时由代码计算：

| 指标           | 计算                                                  |
| -------------- | ----------------------------------------------------- |
| 假设路径覆盖率 | 已对账检查点中，实际落在熊牛区间的比例，按变量列出    |
| 假设路径偏差   | 实际相对中档的平均偏差（按方向）                      |
| 派生对账覆盖率 | 财务派生变量的同类指标                                |
| 开关结局       | 各开关的状态变化序列                                  |
| 价值变动桥汇总 | 整个周期内 V 的变化按分项汇总：哪些假设或事件贡献最大 |
| 收敛           | 是否在窗口内收敛、用时                                |
| 预期回报兑现   | t₀ 到结束的实际回报对比 t₀ 的 R(中)                   |
| 预期差收敛     | 结束时各关键假设的市场隐含值是否向我方中档移动        |
| 交叉验证复核   | 结束时两种方法的价值与实际价格的距离                  |

review-analyst 写判断与教训；结局为证伪，或覆盖率低于 `nominal_coverage − coverage_tolerance` 时教训必填。

### 12.3 持仓周期复盘

持仓周期结束后：收益、对标、超额、override 汇总由代码计算，汇总期间全部决策评估；review-analyst 写归因与教训。清仓后卡回到观察状态。

### 12.4 教训

- 适用范围：本卡 / 行业 / 模板 / 主题 / 变量 / 全局。
- 类型：文本；结构性（必须附规则参数或公式模板的修改提议）。
- "变量遗漏"自动生成结构性教训草稿：提议在行业模板中加入对应变量或开关主题。
- 下一次复查必须逐条确认适用的生效教训。

### 12.5 校准统计

| 统计                                                  | 用途                                                 |
| ----------------------------------------------------- | ---------------------------------------------------- |
| 假设路径覆盖率与偏差（按变量、行业、模板）            | 低于名义覆盖率且样本足够时，提议提高该变量的带宽系数 |
| 派生对账覆盖率                                        | 检验模板公式结构是否合理                             |
| 关键假设命中率（敏感度前 k 的假设是否真的决定了结果） | 检验敏感度规则                                       |
| 倍数中档与推出值、历史分位的偏离与事后表现            | 检验倍数来源规则                                     |
| 交叉验证分歧与事后哪种方法更接近实际                  | 检验方法选择                                         |
| 未量化风险的结局（被量化、证伪或解除）与事后影响      | 检验未量化加成是否合适                               |
| 证伪率、收敛率与收敛时长、未收敛滚动次数              | 报告                                                 |
| 定性判断偏松率、变量遗漏率                            | 驱动模板补充                                         |
| 接入延迟、线索证实率、未解释异动率、时限达成率        | 信息源与流程健康                                     |
| 红灯效力、买点效力、override 胜率                     | 报告                                                 |

`closure_report(card?)` 为只读领域函数。

| 环节       | 检查                                                                            | 级别        |
| ---------- | ------------------------------------------------------------------------------- | ----------- |
