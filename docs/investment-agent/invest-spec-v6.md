## 0. 读法

**数据标记**

| 标记   | 含义                                                                       | 可变性                                 |
| ------ | -------------------------------------------------------------------------- | -------------------------------------- |
| 【事】 | 事实：外部世界已经发生、可观测的值（公告、数据、行情、政策原文、成交回报） | 只追加；修订用新记录加 `supersedes`    |
| 【线】 | 线索：未经官方来源证实的信息（媒体报道、快讯、传闻）                       | 只追加；可被证实或证伪                 |
| 【判】 | 判断：LLM 或用户写下的主张、假设、估计、解释、动作                         | 只能出新版本或新记录                   |
| 【算】 | 计算结果：系统由事实、线索和判断推出                                       | 不接受调用方传入；需要留历史时冻结快照 |
| 【系】 | 系统字段：id、版本号、时间戳                                               | 只由服务端生成                         |

**执行方**

| 标记       | 含义                                        |
| ---------- | ------------------------------------------- |
| 系统       | 确定性代码：接入服务、命令处理器、领域函数  |
| LLM:<岗位> | §4.3 中的某个 LLM 推理岗位，例如 LLM:研究员 |
| 用户       | 使用者本人                                  |

文中数字凡标"示意"者，只用于说明机制，不构成对任何标的的判断。参数名用代码字体，初始值见 §15。

## 1. 一句话模型

> **用户设定目标与边界并承诺资金；LLM 研究公司、提出可证伪的估值逻辑、持续解读事件；系统把逻辑变成可计算的公式，按事件重算、执行护栏、度量每个参与方的表现。目标是长期超额收益，一切管理机制都要说明它怎样服务于这个目标。**

```
                用户：目标与边界 · 资金承诺 · 仲裁 · 私有信息 · 授权
                       ▲ 决策包、打断                     │ 确认、仲裁、输入
                       │                                  ▼
 事件 ───────▶  系统：事实 · 计算 · 状态 · 护栏 · 度量  ◀────▶  LLM：研究 · 估计 · 解读 · 对抗 · 归因
（披露、信息、价格）       │
                       ▼
       逻辑（公式 + 假设 + 杀死条件）→ 定价 → 收益分解 → 允许动作 → 决策 → 成交
                       │
       到期、兑现、证伪、清仓 → 归因（事前与事后的收益分解对比）→ 岗位表现 → 授权与规则
```

## 2. 目标、度量与范围

### 2.1 目标与度量

| 目标                         | 度量                                                                                                                                        | 何时更新                       |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------ |
| **长期超额收益**（第一目标） | 组合相对沪深300 全收益的超额                                                                                                                | 滚动计算，随时可查，不触发动作 |
| 不出大亏                     | 单票亏损超过 `max_loss` 的次数；组合最大回撤                                                                                                | 发生即记录                     |
| 用户的时间                   | 每周用时、被打断次数（§9.11）                                                                                                               | 应用自动记录                   |
| 判断质量                     | 按岗位度量（§12.2）：区间覆盖率、判断兑现率、收益来源一致率、隐含预期判断命中率、事件判断方向命中率、挑战应验率；用户的仲裁与 override 结果 | 每次归因事件后更新             |

### 2.2 实现约束

以下是实现上的约束，服务于 §2.1 的目标，本身不是目标：

1. 逻辑可计算，任何时刻可重算、可追溯每一步；
2. 事件可以落到变量的变化上；
3. 状态由代码推出；
4. 数据完整性与护栏遵守可以由代码检查（§17）。

### 2.3 范围

| 本期包含                                                                                                               | 本期不含                                                            |
| ---------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| A 股个股（沪深北）                                                                                                     | 港股、美股、基金、可转债                                            |

## 3. 设计原则

| #   | 原则                                                                                                                       |
| --- | -------------------------------------------------------------------------------------------------------------------------- |
| R1  | **管理对收益负责**：每条规则写明防哪种错、收益渠道、代价、检验方法（§13）；新规则先证明有用，才能成为硬约束                |
| R2  | **按能力分工，按证据授权**：系统做确定性的事，LLM 做需要推理的事，用户做设定与承诺；LLM 的自主度随其可度量的表现调整（§4） |
| R3  | **严谨程度随阶段递增**：观察阶段一页纸；候选与持仓阶段对关键驱动建完整模型                                                 |
| R4  | **注意力是预算**：只有少数事件打断用户，其余挂到卡上；超出预算时收缩打断范围                                               |
| R5  | **收益来源由分析得出**：系统从当前价格分解预期回报，随事件重算；行为由收益构成和滚动后预期回报决定                         |
| R6  | **事件驱动**：不设日历检查；预期事件没有发生本身是事件                                                                     |
| R7  | **按事件归因学习**：在到期、兑现、证伪、清仓时区分"逻辑对不对"和"收益好不好"                                               |
| R8  | **定性判断有对称的通道**：定性的优势与劣势都通过长期增长段或熊、牛情景表达；无法建模的负面事件才登记为未量化风险           |
| R9  | **LLM 提交判断，系统计算结果**：工具 schema 中不出现【算】【系】字段；LLM 的断言引用事实                                   |
| R10 | **线索不是事实**：可以触发冻结，不能作为事实绑定或对账值                                                                   |
| R11 | **价格只作用于定价**；价格异动只触发找原因                                                                                 |
| R12 | **冲突取保守**：数值作用由代码判定，LLM 只能判得更严，不能更轻                                                             |
| R13 | **先外部视角，再内部视角**：关键增长与利润率假设须说明参照类                                                               |
| R14 | **公式必须安全**：受限表达式语言，用语法树解释执行，禁止 `eval`                                                            |

## 4. 三方分工

### 4.1 分工原则

|          | 擅长                                                              | 不擅长                                                         | 负责                                                         | 不做                                                         |
| -------- | ----------------------------------------------------------------- | -------------------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **系统** | 精确、一致、可复现、不知疲倦                                      | 理解、综合、判断                                               | 数据与出处、计算、状态、事件、护栏、记录、度量               | 任何判断：不挑选变量、不设定区间、不做解释                   |
| **LLM**  | 读懂大量非结构化信息、跨领域综合、提出假说与反例、类比、写推理链  | 算术；凭记忆陈述事实（易编造）；迎合；过度自信；多实例错误相关 | 研究、建模判断、事件解读、决策建议、对抗、归因解释、经验学习 | 产出计算结果、修改状态、绕过护栏、确认交易、陈述无出处的事实 |
| **用户** | 承担资金责任；风险偏好；私有信息与常识；判断该信任 LLM 到什么程度 | 时间和注意力有限；自身的行为偏差                               | 设定目标与边界、资金承诺、仲裁分歧、补充私有信息、调整授权   | 写逻辑、维护模型、处理日常事件                               |

### 4.2 接口约定

| #   | 约定                                                                                                     | 代码保证                                                                         |
| --- | -------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| I1  | LLM 提交判断，不提交结果：变量取值与区间、理由、引用的事实编号、置信度；V、R、收益分解、状态等由系统计算 | 工具 schema 不含【算】【系】字段（`SCHEMA_DERIVED_FIELD_FORBIDDEN`）             |
| I2  | 推理锚定事实：每个断言引用事实编号；未引用的断言标为"推断"                                               | 引用的事实必须存在，且 `disclosed_at` 不晚于判断时间（`FACT_REF_INVALID`）       |
| I3  | 判断带置信度（高 / 中 / 低）和"什么会改变我的看法"                                                       | schema 必填；后者作为杀死条件的候选                                              |
| I4  | 系统把 LLM 的历史表现与经验库喂回 LLM                                                                    | 读接口 `get_role_performance`、`get_experiences`；推理的输入引用记入 LlmJudgment |
| I5  | 用户面对决策包，而不是表单                                                                               | §11.6                                                                            |
| I6  | 每次 LLM 推理的输入、输出、模型都留痕                                                                    | LlmJudgment 关联 turn-trace 的 `trace_id`                                        |

### 4.3 LLM 推理岗位

| 岗位       | agent                                            | 何时运行                         | 推理任务                                                                                                                                 | 系统校验与度量                                                                 |
| ---------- | ------------------------------------------------ | -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 研究员     | `stock-research`（每张卡一个上下文）             | 立论、候选建模、复查、滚动、证伪 | 研究商业模式、行业格局与竞争；解读市场隐含预期；提出论点；选关键驱动并给区间与参照类；写情景叙事与杀死条件；转换待转换条目；给出决策建议 | 完备性、出处、覆盖；区间覆盖率、判断兑现率、收益来源一致率、隐含预期判断命中率 |
| 三视角估计 | `estimator`（以视角参数区分）                    | 立论、重写，只针对关键驱动       | 自下而上、自上而下、外部视角各自独立估计 T 期中档                                                                                        | §5.6 区间规则；各视角误差                                                      |
| 事件分析   | `event-analyst`（接入服务内调用，无写工具）      | 信息到达；不利异动               | 抽取结构化信息；判断影响的变量、方向、幅度区间、是否已定价、可信度；检索异动原因与线索的官方来源                                         | schema 校验；暂定 ΔV 由系统算；方向命中率                                      |
| 反方       | `short-thesis`（隔离上下文，可配置不同厂商模型） | 立论；建仓、加仓前；重写         | 事前验尸（"一年后亏了 30%，最可能的原因"）；寻找反证；构建最强空头叙事；检查重写是否在移动球门                                           | 必须引用研究员未用过的事实（`CHALLENGE_NO_NEW_EVIDENCE`）；挑战应验率          |
| 复盘分析   | `review-analyst`                                 | 归因事件之后；校准之后           | 解释归因结论；跨卡寻找系统性偏差；起草规则、模板、参数的修改提议；写经验库                                                               | 提议走 §13.4                                                                   |
| 专项研究   | `industry-research`、`macro-research`            | 研究员委托                       | 行业、宏观的取数与分析                                                                                                                   | 无写命令                                                                       |
| 助手       | 对话入口                                         | 用户随时发起                     | 解释任何数字与判断；把用户的私有信息交给研究员纳入逻辑                                                                                   | 修改走同样的校验                                                               |
| 发现（P4） | `scout`                                          | 筛选                             | 推荐候选标的                                                                                                                             | —                                                                              |

**独立性**：三视角估计的三个上下文互不可见，也看不到研究员的草案；反方看得到逻辑，但必须引用研究员未用过的事实，并可配置为另一厂商的模型。

### 4.4 用户的职责

1. **设定**：目标、风险预算（`max_loss`、仓位上限）、注意力预算、覆盖范围（`set_budgets`）。
2. **资金承诺**：确认建、加、减、清（`confirm_decision`）；在券商下单并录入成交（`record_trade`）。
3. **仲裁**（§10.5）：三视角分歧过大、研究员与反方结论相反、LLM 对交易建议的置信度为低、持仓阶段要重写逻辑。
4. **补充**：私有信息与看法（`add_user_input`），以"用户"为出处记录。研究员引用用户输入修改逻辑时，必须列出支持与反对证据（`USER_INPUT_NO_EVIDENCE`）。
5. **授权**：按 LLM 的表现调整授权等级（`set_autonomy`）；批准规则、模板、参数的变更（`approve_rule_change`）。

用户不写逻辑、不维护模型、不处理日常事件；可以随时否决一个逻辑（`veto_thesis`）。

### 4.5 授权分级

交易永远由用户确认；授权只决定逻辑维护由谁拍板。

**A0（首期默认）**

| 事项               | 观察     | 候选     | 持仓               |
| ------------------ | -------- | -------- | ------------------ |
| 立论、修订、重写   | LLM 生效 | LLM 生效 | 用户确认           |
| 待转换条目的转换   | LLM 生效 | LLM 生效 | 用户确认（随复查） |
| 滚动或结束         | LLM 生效 | LLM 生效 | 用户确认           |
| 建、加、减、清     | —        | 用户确认 | 用户确认           |
| 持有、等待         | 自动记录 | 自动记录 | 自动记录           |
| 解除线索或异动冻结 | 用户     | 用户     | 用户               |

建仓、加仓时用户在决策包中审阅当时的逻辑版本，确认决策即认可该版本。

**A1**：在 A0 基础上，持仓阶段不放宽杀死条件、不改变允许动作的修订与滚动由 LLM 生效；重写与结束仍需用户确认。

**升级与降级**：研究员的关键驱动区间覆盖率 ≥ `nominal_coverage − coverage_tolerance`、样本数 ≥ `calib_min_n`，且窗口内没有 H3 或授权违规时，系统提议升级，用户批准；覆盖率在最近 `calib_min_n` 个样本上跌破阈值时自动降回 A0 并通知用户。越权提交被拒绝（`AUTONOMY_EXCEEDED`）。升级阈值待检验（§21）。

### 4.6 LLM 可靠性机制

| 风险                  | 机制                                           |
| --------------------- | ---------------------------------------------- |
| 算错                  | 数字一律由系统计算（I1、H2）                   |
| 编造事实              | 断言引用事实编号并核验（I2、H1）               |
| 过度自信              | 三视角决定区间下限（§5.6）；校准反馈（I4）     |
| 事后合理化、移动球门  | 杀死条件不能放宽（H3）；反方检查重写           |
| 多个 LLM 实例错误相关 | 上下文隔离；反方必须用新事实；可换厂商模型     |
| 迎合用户              | 引用用户输入时必须列支持与反对证据             |
| 讲故事替代证据        | 收益来源由系统计算，与论点叙述并排对照（§6.4） |
| 前视偏差              | 回测只检验机械规则（§13.3）                    |

### 4.7 成本控制

- 三视角估计只用于关键驱动，只在立论和重写时运行。
- 事件分析只处理粗筛命中并路由到卡的条目；每日上限 `llm_daily_event_analyses`，超出按优先级排队（否决类 > 持仓卡 > 候选卡 > 观察卡），积压时健康告警。
- 反方只在立论、建仓与加仓前、重写时运行。
- 投研 agent 只暴露命令类工具，取数经服务端取数注册表（§20 P0）；用 turn-trace 度量每次推理的输入规模与耗时。

## 5. 逻辑与判断内核

### 5.1 定义

> **逻辑（Thesis）是一个以估值公式表达、可计算、可证伪的价值主张。** 在时间窗 [t₀, T] 内，资产价值由宏观、行业、公司变量通过确定的公式算出；每个变量要么绑定事实，要么是带区间、理由和证伪条件的假设；主张是：按此公式，在基准和熊市情景下，从现在持有到 T 的回报满足要求。

```
V_T(s) = F( 事实变量(t),  假设变量(s, 各期),  情景开关(s) )          s ∈ {熊, 中, 牛}
coe    = rf + β × ERP
V₀(s)  = ( V_T(s) + D(s) ) ÷ (1 + coe)^τ

主张：  ( V_T(中) + D ) ÷ P ≥ (1 + h)^τ        且        ( V_T(熊) + D ) ÷ P ≥ 1 − max_loss
```

h 为有效回报门槛（§8.4），τ 为距 T 预计披露日的年数，D 为期间分红。**T 由逻辑所需证据的披露时点决定**：估值输入假设的最后一个检查点，按预计披露日到期，不早于下一个可披露报告期，不超过 `max_horizon_periods`（`HORIZON_INVALID`）。

| 时点     | 含义                                           |
| -------- | ---------------------------------------------- |
| t₀       | 逻辑版本冻结时间；只能使用 t₀ 之前已披露的事实 |
| 检查点   | 假设路径上的每一期，按预计披露日到期           |
| T        | 估值输入假设的最后一个检查点                   |
| 收敛窗口 | 倍数部分需要时，预计市场重新定价的时间段       |

**生命周期**：active（T 的观测尚未披露）→ due（T 的观测已披露，滚动或结束尚未确认）→ superseded（被新版本接替）/ completed（结束）/ falsified（杀死条件触发且不重写）/ abandoned（放弃或被用户否决）。

**版本类型**（系统比较新旧版本判定）：新立（卡上没有 active 逻辑）；修订（结构不变，只改路径数值、开关映射数值、倍数中档、收敛条件，且不放宽杀死条件）；重写（变量或公式增删改、开关增删、估值方法改变，或放宽任一杀死条件）；滚动（结构不变，T 后移并给出新路径）。逻辑周期从一次新立或重写开始，到下一次重写、结束、证伪或放弃为止。

### 5.2 卡的阶段

| 阶段 | 判定（系统）                                                                                                                                                 | 逻辑形态           |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------ |
| 观察 | 未归档、无持仓、不满足候选条件                                                                                                                               | 一页纸（通用模板） |
| 候选 | 无持仓，且现价 ≤ 买点价 × (1 + `candidate_distance`)、或定价低估、或用户要求建仓；现价回到买点价 × (1 + 2 × `candidate_distance`) 以上且无建仓意图时退回观察 | 完整模型           |
| 持仓 | 持仓 > 0                                                                                                                                                     | 完整模型           |
| 归档 | 停止覆盖                                                                                                                                                     | —                  |

### 5.3 一页纸

| #   | 项             | 内容                                                                        | 执行方                                       |
| --- | -------------- | --------------------------------------------------------------------------- | -------------------------------------------- |
| 1   | 市场隐含了什么 | 反向 DCF 隐含增速；关键驱动按当前倍数反解的隐含值（§8.6）；市场在定价的叙事 | 系统计算；LLM:研究员 解读                    |
| 2   | 我方看法       | 论点（市场错在哪）；1–3 个关键驱动的中档、区间、理由、参照类；三视角估计    | LLM:研究员、LLM:三视角估计                   |
| 3   | 收益来源       | 收益分解与标签（§6）                                                        | 系统                                         |
| 4   | 熊市情景       | 熊情景叙事；R(熊)；由 H5 得出的仓位上限                                     | LLM:研究员（叙事）；系统（数值）             |
| 5   | 杀死条件       | 2–3 条，覆盖规则见 §5.8                                                     | LLM:研究员 起草，LLM:反方 挑战，系统校验覆盖 |
| 6   | 价格           | 买点价、减仓点（V₀(牛)）                                                    | 系统                                         |

一页纸用通用模板：营收增速、净利率（或毛利率与费用率）作为公司层驱动变量，PE_T 由 §7.5 确定，长期增长段按 §7.5 登记；业务驱动（份额、价格、产能等）写在理由与先行指标中。六项任一缺失即拒绝（`KERNEL_INCOMPLETE`）。

### 5.4 完整模型

候选与持仓阶段使用。行业有经营模板时必须基于模板（`TEMPLATE_REQUIRED`），只对关键驱动所在的分支展开，其余变量可以用公司层汇总假设。

**变量五层**

| 层   | 含义                         | 例子                                                           |
| ---- | ---------------------------- | -------------------------------------------------------------- |
| 宏观 | 经济、政策、利率             | 乘用车总销量、社零增速、10 年期国债收益率、LPR、购置税减免状态 |
| 行业 | 行业规模、结构、价格、成本   | 新能源渗透率、行业均价变化、碳酸锂价格变化、高端白酒批价       |
| 公司 | 公司经营的驱动               | 份额、单价、单位成本、费用率、海外销量、贷款增速、净息差       |
| 财务 | 财务结果，**只能由公式推出** | 营收、毛利率、净利、扣非 EPS、ROE、BVPS、自由现金流、DPS       |
| 估值 | 把财务结果变成价值           | PE_T、PB_T、coe、V_T、V₀                                       |

**变量类型**

| 类型     | 含义                                       | 取值来源                                         |
| -------- | ------------------------------------------ | ------------------------------------------------ |
| 事实变量 | 当前可观测的量                             | 事实绑定，自动更新                               |
| 假设变量 | 未来值需要预测的量                         | 各期路径（熊、中、牛）                           |
| 派生变量 | 由公式计算的量                             | 公式                                             |
| 情景开关 | 离散的外部条件                             | 当前状态取自事实或复查结论；各情景取值由情景定义 |
| 常量     | 有出处的固定值（如法定税率、电池成本占比） | 引用事实或法规（`CONSTANT_NO_SOURCE`）           |
| 参数     | 规则参数中的全局值（如 ERP）               | RuleParams                                       |

每个叶子变量必须是事实、假设、情景开关、有出处的常量或参数之一（`LEAF_UNBOUND`）。

**财务层**：营收、净利、扣非 EPS、ROE、BVPS、自由现金流、DPS 等只能由公式推出（`RESULT_ASSUMED`）。毛利率、费用率在行业模板中由公式推出；通用模板没有经营细分时，营收增速、毛利率、费用率作为公司层驱动变量登记为假设，净利、EPS 仍须由公式推出。

**时间维度与口径**

- 每个变量声明频率（月 / 季 / 年）与口径（单期、年初至今累计、TTM、期末存量），按期展开；公式按期计算，检查点和 T 都对应某一期。
- 流量按期求和；比率由同口径的分子、分母重算，**不对比率取平均**；存量取期末值。
- 年度变量的季度检查点按"年初至今累计"登记路径点，与同口径观测对账；月度观测用于先行验证，不直接对账年度路径。
- 观测进入对账前按变量口径换算；换算所需的期次缺失时不对账，生成数据缺失事件并自动补取；口径无法换算时拒绝绑定（`PERIOD_BASIS_MISMATCH`）。
- **股本**：存在未转股可转债、已披露的增发预案或在实施的股权激励时，股本必须登记为假设，不能作为事实（`DILUTION_UNMODELED`）。

**公式语言**

- 每个派生变量一条公式，附**机制说明**（为什么这个关系成立）。
- 受限表达式语言，解析为语法树后解释执行，**不使用 `eval`**。允许：数字、变量引用（可带期偏移，如 `revenue[-1]`）、`+ − × ÷ ^`、`min`、`max`、`clamp`、`sum`（对分部求和）、`sw(开关, {状态: 值, …})`。不允许其他函数、字符串、自定义函数、递归（`FORMULA_SYNTAX`、`FORMULA_FUNCTION_FORBIDDEN`）。
- 系统检查：引用存在、无环（`FORMULA_UNKNOWN_VARIABLE`、`FORMULA_CYCLE`）、**量纲一致**。单位由基本单位（元、辆、股、吨、年）与数量级前缀（万 = 10⁴、亿 = 10⁸）组成：量纲按基本单位比较，前缀在求值时换算；"亿元 + 辆"拒绝（`UNIT_MISMATCH`）；同量纲不同前缀相加换算后求值并警告（`UNIT_SCALE_MIXED`）。单位为 `%` 的变量进入公式时自动按比率处理。三个情景都必须能算出 V_T（`VALUATION_NOT_COMPUTABLE`）。

### 5.5 假设与关键驱动

**关键驱动**：对假设与长期增长段做敏感度排序（§8.7），前 `key_top_k` 个自动成为关键驱动；LLM:研究员 可以追加，不能删除。估值层倍数不是假设，取值与约束见 §7.5。

| 要素                                                       | 关键驱动                           | 非关键变量 |
| ---------------------------------------------------------- | ---------------------------------- | ---------- |
| 主体与指标                                                 | 必填                               | 必填       |
| 锚（T1 或 T2、在新鲜窗内；无本体历史时引用可比对象并标记） | 必填                               | 可选       |
| 预测方式                                                   | 相对锚的增量或倍数；给绝对值时警告 | 任意       |
| 各期路径（熊、中、牛）                                     | 每个检查点                         | 只需 T     |
| 理由（引用事实或事件）                                     | 必填                               | 必填       |
| 参照类（增长与利润率类）                                   | 必填                               | —          |
| 三视角估计                                                 | 必填（立论、重写）                 | —          |
| 外部驱动（宏观、行业层变量或情景开关）                     | 缺失时警告                         | —          |
| 证伪规则 `{指标, 比较符, 阈值, 连续期数}`                  | 必填（构成杀死条件）               | 可选       |
| 先行指标或先行检查点                                       | 至少一个                           | —          |

缺项报 `KEY_ASSUMPTION_INCOMPLETE`、`ASSUMPTION_NO_ANCHOR` / `ANCHOR_TIER_TOO_LOW` / `ANCHOR_STALE`、`KEY_NO_REFERENCE_CLASS`、`ESTIMATES_REQUIRED`、`ASSUMPTION_NO_RATIONALE`。路径须按时间递增、每点熊 ≤ 中 ≤ 牛（按方向）、终点为 T（`PATH_INVALID`）；关键驱动每点带宽不低于 §8.8 的下限（`BAND_TOO_NARROW`）。

### 5.6 三视角估计

| 视角     | 依据                                       |
| -------- | ------------------------------------------ |
| 自下而上 | 公司数据：产能、订单、渠道、产品结构       |
| 自上而下 | 行业总量与结构、宏观约束、份额推算         |
| 外部视角 | 参照类：同类公司在类似规模或阶段的历史分布 |

- 三个上下文互不可见，也看不到研究员的草案；各自给出 T 期中档、理由与引用（`submit_estimate`）。
- **区间规则**：关键驱动在 T 的熊档不得优于三视角中最不利的估计，牛档不得劣于最有利的估计（按指标方向），否则拒绝（`BAND_BELOW_ESTIMATES`）。
- 研究员的中档应落在三视角范围内，否则须说明理由（`ESTIMATE_OUTSIDE_RANGE`，警告）。
- **分歧度** = 三视角最大值与最小值之差 ÷ 研究员中档的绝对值。超过 `estimate_dispersion_max` 时：观察阶段只记录；候选与持仓阶段需要用户仲裁（§10.5）。

### 5.7 情景开关与情景

**情景开关**表示无法用连续数值表达的外部条件，可选，每个逻辑不超过 2 个。

| 要素             | 说明                                              |
| ---------------- | ------------------------------------------------- |
| 主题             | 关联主题词典，事件通过主题路由到开关              |
| 状态             | 例如购置税减免：延续 / 减半 / 取消                |
| 每个状态的严重度 | 基准 / 削弱 / 破坏，立逻辑时写下                  |
| 每个状态的映射   | 该状态下哪些假设如何调整，例如"减半：渗透率 −3pp" |
| 当前状态         | 立论时由事实确定；之后由复查中的情景切换改变      |

开关每个状态须有严重度与映射，且至少一个"破坏"状态（`SWITCH_INCOMPLETE`）。

**情景**是三套连贯的取值组合：

| 情景     | 定义规则                                                                                                                                  |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 中       | 所有假设取中档；情景开关取当前状态                                                                                                        |
| 熊       | LLM:研究员 写一条连贯的下行叙事，指定哪些假设取熊档、哪些开关取哪个状态；**必须包含关键驱动中的至少 k − 1 个**（`SCENARIO_INCONSISTENT`） |
| 牛       | 连贯的上行叙事，规则同上；定性优势在这里与长期增长段中表达（R8）                                                                          |
| 压力测试 | 所有关键驱动同时取熊档、所有开关取最坏状态；只展示                                                                                        |

### 5.8 杀死条件与收敛条件

**杀死条件**是立论时写下、提交后不能放宽的证伪规则：

| 来源       | 形式                                                      |
| ---------- | --------------------------------------------------------- |
| 关键驱动   | 该驱动的证伪规则                                          |
| 长期增长段 | 滚动复合增速的证伪规则（§7.5）                            |
| 倍数部分   | 收敛条件连续 `max_rolls_without_convergence` 个窗口未兑现 |
| 反方       | 已采纳挑战对应的条件                                      |

- **覆盖**：收益分解中占比 ≥ `kill_coverage_share` 的每个正向部分至少有一条杀死条件（`KILL_COVERAGE_MISSING`）；已采纳的挑战必须被覆盖（`CHALLENGE_NOT_COVERED`）。
- **数量**：一页纸 2–3 条；完整模型不超过 `kill_max` 条。
- **不可放宽（H3）**：放宽阈值、延长连续期数、删除杀死条件，版本类型一律判为重写，确信度归零，并计入过程审计（§12.1）。
- **收敛条件**：倍数部分占比 ≥ `kill_coverage_share` 时必填，写明催化事件、关联变量与时间窗（`CONVERGENCE_NO_WINDOW`）。盈利部分的兑现就是各检查点的披露，不另写。

### 5.9 完备性规则

逻辑落库前由系统检查。**错误**拒绝提交；**警告**展示并记录，不阻断。

## 6. 收益来源

### 6.1 分解

```
EPS₀ = 当前扣非 EPS（TTM）；PE₀ = P ÷ EPS₀
g_E  = EPS_T ÷ EPS₀ − 1              周期股用 EPS_norm
g_M  = PE_T(中) ÷ PE₀ − 1
d    = D ÷ P
1 + R(中) = (1 + g_E) × (1 + g_M) + d

对数贡献（可直接相加）：
c_E = ln(1 + g_E)
c_M = ln(1 + g_M)
c_D = ln(1 + R(中)) − c_E − c_M
占比 = 某正向部分的贡献 ÷ 全部正向贡献之和；负向部分记为拖累项
```

其他方法同口径：PB-ROE 为 BVPS 增长、PB 变化、分红；PS 为营收增长、PS 变化。每次定价重算（立论、复查、价格与事实事件）都从**当前价格**重新分解，结果写入定价快照。

### 6.2 标签

只用于展示、统计和与论点对照，不驱动任何动作。

| 标签     | 条件（按顺序）                                                                                                                 |
| -------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 混合     | 最大的正向部分占比 < `source_primary_share`；同时显示前两项                                                                    |
| 分红     | 分红部分是最大的正向部分                                                                                                       |
| 估值修复 | 倍数部分是最大的正向部分                                                                                                       |
| 周期     | 标的画像为周期性，盈利部分来自正常化                                                                                           |
| 拐点     | 盈利部分最大，且当前扣非 EPS 低于近 5 年中位数 × `eps_depressed_ratio` 或为亏损（PS 方法中营收部分最大且盈利路径给出扭亏年份） |
| 成长     | 其余盈利部分最大的情况                                                                                                         |

### 6.3 由计算驱动的行为

| 行为                 | 规则                                                                                                                               |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 杀死条件覆盖         | 占比 ≥ `kill_coverage_share` 的每个正向部分至少一条杀死条件（§5.8）                                                                |
| 收敛条件             | 倍数部分占比 ≥ `kill_coverage_share` 时必填                                                                                        |
| 滚动还是结束         | 到期事件、或倍数主导的兑现事件发生时，系统生成滚动草案并计算滚动后预期回报：达到持有门槛默认滚动并持有，否则默认结束并减仓（§8.5） |
| 滚动上限计数         | 只在"关键驱动在 T 未兑现"或"倍数部分占比 ≥ `roll_count_multiple_share`"时计数；关键驱动已兑现、只是价格滞后的滚动不计数            |
| PEG 与长期增长段必填 | 盈利部分占比 ≥ `growth_rules_share` 时适用（§7.5、§7.6）                                                                           |

### 6.4 论点一致性

论点的叙述与计算出的收益来源并排展示；论点声称盈利增长而倍数部分是最大的正向部分时警告（`RETURN_SOURCE_MISMATCH`），研究员须解释。收益来源标签发生变化（例如估值修复完成后变为成长）时，作为事件挂到卡上。

## 7. 估值方法

### 7.1 默认方法：前瞻 PE

```
V_T = 扣非 EPS_T × PE_T
```

EPS 口径为扣非 EPS，由经营模型推导到 T 所在的会计年度；不允许直接假设 EPS。大多数标的走这条路径，例外由标的画像自动判定。

### 7.2 标的画像（AssetProfile）

| 维度     | 取值                                                                 | 判定                                                                                               |
| -------- | -------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| 行业组   | 金融-银行 / 金融-券商 / 金融-保险 / 周期 / 资源 / 地产 / 公用 / 一般 | 系统：行业分类 → 行业组映射                                                                        |
| 盈利状态 | 稳定盈利 / 亏损或微利 / 周期性                                       | 系统：最近 TTM 扣非净利 ≤ 0 为亏损；近 5 年扣非净利变异系数 > `cyclical_cv` 或属周期行业组为周期性 |
| 分红特征 | 高股息 / 一般                                                        | 系统：近 3 年平均分红率 ≥ 50% 且股息率 ≥ 4%                                                        |
| 业务结构 | 单一 / 多元                                                          | 系统：最大分部收入占比 < 60% 且分部数 ≥ 2 为多元                                                   |
| 价值来源 | 经营 / 资产重估 / 管线                                               | LLM:研究员 判断，系统校验与其他维度不冲突                                                          |

画像随资格评估一起生成；年报披露事件后重新评估。

### 7.3 画像 → 方法

| 画像（按顺序匹配）               | 主方法              | 交叉验证                                                 | 本期   |
| -------------------------------- | ------------------- | -------------------------------------------------------- | ------ |
| 金融-保险                        | P/EV                | PB                                                       | 不支持 |
| 金融-银行、金融-券商             | PB-ROE              | 股息率                                                   | 支持   |
| 资源、地产，或价值来源为资产重估 | NAV                 | PB                                                       | 不支持 |
| 价值来源为管线                   | rNPV                | PS                                                       | 不支持 |
| 多元                             | SOTP                | PE                                                       | 不支持 |
| 亏损或微利                       | PS + 盈利路径       | 远期 PE 折现                                             | 支持   |
| 周期性                           | 正常化盈利 PE       | PB                                                       | 支持   |
| 其余（稳定盈利）                 | **前瞻 PE（默认）** | 高股息用股息率；模板含现金流模块时用 DCF；其余用反向 DCF | 支持   |

不支持的画像可以建卡、做资格评估、接收信息，但不能提交逻辑（`METHOD_NOT_SUPPORTED`）。

### 7.4 方法估值模板

| 方法                 | 估值层公式                                                                                                                                                                            |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 前瞻 PE              | `V_T = EPS_T × PE_T`                                                                                                                                                                  |
| PB-ROE               | `BVPS_T = BVPS₀ + Σ EPS − Σ DPS`；`V_T = BVPS_T × PB_T`；推出值 `PB = (ROE_T − g) ÷ (coe − g)`                                                                                        |
| 正常化盈利 PE        | `EPS_norm = BVPS_T × ROE_norm`（ROE_norm 为近一个完整周期的平均 ROE，假设）；`V_T = EPS_norm × PE_norm`                                                                               |
| PS + 盈利路径        | `V_T = 营收_T × PS_T`；同时给出盈利路径：盈亏平衡期、目标净利率、目标年份 Y；交叉验证 `V_T' = 营收_Y × 目标净利率 ÷ N × PE_Y ÷ (1 + coe)^(Y − T)`                                     |
| DCF（交叉验证）      | `企业价值 = Σ FCFF ÷ (1 + WACC)^t + 终值`；`股权价值 = 企业价值 − 净负债`；FCFF 由经营模型推出（需模板含现金流模块）                                                                  |
| 反向 DCF（交叉验证） | 已知 P、当前扣非 EPS₀、退出倍数 PE_exit（取 §7.5 中档）、coe、年数 n（= 长期增长段 n）：`g_implied = (P × (1 + coe)^n ÷ (EPS₀ × PE_exit))^(1/n) − 1`；与 g₁ 比较（复用 `reverseDcf`） |
| 股息率（交叉验证）   | `V = DPS_{T+1} ÷ (coe − g)`，g ≤ `g_terminal_cap`                                                                                                                                     |

### 7.5 倍数来源

PE_T、PB_T、PE_norm、PS_T 都按以下规则确定。倍数是估值层的取值，不是 §5.5 意义上的假设；决定合理倍数的长期增长段是假设。

| 步骤                 | 规则                                                                                                                                                                                                                                                             |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ① 相对历史分位定区间 | 倍数序列用**相对基准**口径：标的扣非 TTM PE ÷ 基准 PE（`relative_multiple_benchmark`），取 `multiple_history_years` 年分位，再乘以当前基准 PE 折回绝对值。熊 = `p_bear` 分位，牛 = `p_bull` 分位，中档候选区间为 `[p_center_lo, p_center_hi]` 分位               |
| ② 基本面推出值       | PE：两段式 `PE_T = Σ_{i=1..n} 分红率₁ × x^i + 分红率₂ × (1 + g₁)^n × (1 + g₂) ÷ ((coe − g₂) × (1 + coe)^n)`，`x = (1 + g₁) ÷ (1 + coe)`；PB：`(ROE − g) ÷ (coe − g)`。`g₂ ≤ g_terminal_cap`，`coe − g₂ ≥ min_spread`。按 g₁ 的熊、中、牛得到 J(熊)、J(中)、J(牛) |
| ③ 中档               | 须落在 ① 的中档候选区间内，或在 J(中) × (1 ± `justified_tolerance`) 内，否则拒绝（`MULTIPLE_CENTER_OUT_OF_RANGE`）。只满足其中一个时，须说明市场为何偏离历史或基本面                                                                                             |
| ④ 熊档               | 取 ① 的 `p_bear` 分位与 J(熊) 的**较低者**                                                                                                                                                                                                                       |
| ⑤ 增速换挡           | 画像变化，或 g₁(中) 与近 `multiple_history_years` 年实际扣非 EPS 复合增速相差超过 `regime_shift_gap` 时，① 只作参照，中档以 J(中) 为准（须在 ③ 的容差内）                                                                                                        |
| ⑥ 同业分位参照       | 同行业可比公司的同口径倍数分位，只报告                                                                                                                                                                                                                           |
| 历史不足             | 不足 `multiple_min_years` 年：熊 = 中 × `fallback_bear_factor`                                                                                                                                                                                                   |

**长期增长段是可证伪的假设**：g₁、n、分红率₁ 登记为估值层假设——锚为近 3 至 5 年实际扣非 EPS（或营收）复合增速；先行指标至少一个（资本开支强度、产能投放、研发投入、新业务收入占比等）；证伪规则作用于滚动复合增速。它们进入推出值，再经 ③④ 进入倍数与 V，因此参与敏感度排序，可以成为关键驱动。盈利部分占比 ≥ `growth_rules_share` 时，锚、先行指标和证伪规则必填（`LONG_GROWTH_UNFALSIFIABLE`）。

推出值使 coe 进入倍数：利率下行时推出的合理倍数上升，经 ③④ 影响中档与熊档，这是宏观作用于估值的定量通道。

### 7.6 PEG 检查

盈利部分占比 ≥ `growth_rules_share` 时：`PEG = PE_T(中) ÷ (g₁(中) × 100)`，增速取长期增长段 g₁，不用不足一年的短期增速。超过 `peg_max` 时警告（`PEG_TOO_HIGH`），研究员须说明理由。

### 7.7 交叉验证与分歧

```
分歧 = |V_T(中, 主方法) − V_T(中, 交叉验证)| ÷ V_T(中, 主方法)
```

超过 `cross_check_divergence` 时研究员必须说明原因。交叉验证为反向 DCF 时按增速比较：`分歧 = g₁(中) − g_implied`（百分点），超过 `implied_growth_gap` 时同样须说明。分歧计入门槛的加成（`p_divergence`）待检验，默认关闭。

### 7.8 行业经营模板

| 行业 | 方法                      | 核心变量与公式骨架                                                                                                      | 推荐的情景开关主题                     |
| ---- | ------------------------- | ----------------------------------------------------------------------------------------------------------------------- | -------------------------------------- |

画像变化导致主方法变化时，必须提交新版本，版本类型为重写。

## 8. 定价

### 8.1 V_T

按情景分别求值：三个情景的变量取值代入公式，按期计算到 T，得到 V_T(熊)、V_T(中)、V_T(牛) 和每一步的中间值（计算过程完整保留，供界面展示）。

### 8.2 资本成本、分红与 V₀

```
rf  = 10 年期国债收益率最新观测
β   = 对沪深300 的周收益回归（beta_window_weeks），Blume 调整 0.67β + 0.33；数据不足取 1
coe = rf + β × ERP
D   = 现在到 T 的预期分红（由 DPS 推出；模型没有 DPS 时取最近一期每股分红事实 × 期间年数）
τ   = 现在到 T 预计披露日的年数（不小于 0）
V₀  = (V_T + D) ÷ (1 + coe)^τ
```

rf 的新观测对所有逻辑触发"只改定价"的重算。

### 8.3 预期回报

```
R(中) = (V_T(中) + D) ÷ P − 1      年化：(1 + R)^(1/τ) − 1（τ < 0.25 时按 0.25 处理）
R(熊) = (V_T(熊) + D) ÷ P − 1
```

**情景加权期望（只展示，待检验）**：研究员在情景定义中给出熊、中、牛的主观概率（和为 1）；系统计算 `E[R] = Σ p(s) × R(s)` 与偏度 `(R(牛) − R(中)) ÷ (R(中) − R(熊))`，不进入买点与状态判定。

### 8.4 有效门槛与买点

```
h = hurdle_base
  + premium_grade[资格等级]
  + p_width × (V_T(牛) − V_T(熊)) ÷ V_T(中)
  + Σ 未量化风险加成
  上限 hurdle_cap

买点价 = min( (V_T(中) + D) ÷ (1 + h)^τ ,  (V_T(熊) + D) ÷ (1 − max_loss) )
```

待检验分项（默认 0，回放证明有用后经规则清单启用）：`p_unverified`（未验证的关键驱动比例）、`p_time`（τ）、`p_divergence`（交叉验证分歧）、`p_multiple`（倍数与推出值冲突）、历史不足加成。

### 8.5 持有门槛与滚动

到期事件（T 的观测披露），或倍数主导的兑现事件（倍数部分占比 ≥ `roll_count_multiple_share` 且价格收敛到 V₀(中) 的 `convergence_tol` 以内，或收敛条件中的催化事件发生）发生时：

```
滚动草案：T' = T 之后的下一个检查点；结构不变，下一期路径由研究员补充
R_roll  = (V_T'(中) + D') ÷ P − 1，τ' = 现在到 T' 预计披露日的年数
默认动作：1 + R_roll ≥ (1 + hold_hurdle)^τ' → 滚动并持有；否则 → 结束（有持仓时减或清）
```

默认动作在持仓阶段需用户确认（A0），在观察与候选阶段由研究员生效。达到滚动上限（计数条件见 §6.3）后不能再滚动（`ROLL_LIMIT_REACHED`），倍数部分的杀死条件触发。

### 8.6 市场隐含值与预期差

对每个关键驱动：其他变量取中档，在该变量合理区间内二分求解使 V₀(中) = P。分别在**当前倍数**（当前扣非 TTM PE 保持到 T）与**我方倍数**（PE_T 中档）下求解，两者都展示；预期差与 `NO_VARIANT_GAP` 以当前倍数下的隐含值判定。

```
隐含值 x*：V₀(中)(x*) = P
预期差 = (我方中档 − x*) ÷ |x*|，按方向修正
```

不单调或无解时记为"无法反解"。研究员据此解读市场在定价什么叙事。

### 8.7 敏感度与关键驱动

对每个假设、长期增长段和倍数：其他取中档，该变量分别取熊档和牛档，计算 V_T(中) 的变化幅度并排序（龙卷风图）。假设与长期增长段中的前 `key_top_k` 个自动成为关键驱动；倍数只展示。

### 8.8 路径带宽下限

```
sigma = 该指标最近 band_history_periods 期相邻变化的标准差
每个检查点最小带宽 = band_min_k × sigma × sqrt(该检查点距锚的期数)
```

历史不足 `band_min_history` 期时跳过此下限；关键驱动在 T 的区间同时须覆盖三视角（§5.6）。

### 8.9 定价状态

| 状态   | 条件（按顺序）                                                  |
| ------ | --------------------------------------------------------------- |
| 过期   | 关键驱动的检查点数据缺失超过 `disclosure_grace_days` 且补取未果 |
| 待滚动 | 到期或倍数主导的兑现事件之后，滚动或结束尚未生效                |
| 高估   | P ≥ V₀(牛)                                                      |
| 低估   | P ≤ 买点价                                                      |
| 合理   | 其余                                                            |

### 9.3 接入流水线

```
拉取 → 原始信息
  → ① 去重：URL、内容哈希、近似哈希（dedupe_simhash_window_hours）
  → ② 粗筛（系统）：标的名称与代码、行业、主题关键词与别名、指标名的字典匹配；未命中只存档
  → ③ 事件分析（LLM，仅命中条目）：摘要、事件类型、涉及对象、候选数值；对每张命中的卡给出暂定判断
  → ④ 合并标签：代码匹配 ∪ 抽取结果（抽取只能增加）
  → ⑤ 生成事实：official → 事件与观测；commercial（白名单）→ 观测（T2）；media → 线索
  → ⑥ 即时对账与重算（§9.6）
  → ⑦ 生成卡事件；按 §9.11 打断或挂卡；冻结按 H7
```

### 9.4 事件分析的约束

- 没有写入工具；输出通过 schema 校验后由系统写入（`record_event_judgment`）。
- 只能增加标签，不能决定作用或是否打断。
- 候选数值只有来源为 official 或白名单 commercial、且通过观测校验后才成为事实。
- **暂定判断** `{变量, 方向, 幅度区间, 是否已定价（是 / 部分 / 否）, 可信度, 置信度}`：系统按幅度区间中点算出暂定 ΔV(中)，只用于打断与累计判断，不改变定价快照；正式变化在复查中由研究员转换后生效。
- 对已由代码判定作用的对账，暂定判断只能更严（`EFFECT_CONFLICTS_COMPUTED`）。

### 9.5 线索

- 否决级线索（如"传立案调查"）冻结建仓、加仓（H7），事件分析同时检索官方来源。
- 找到官方来源：关联并按官方条目处理；核实为不实：解除冻结。
- 既未证实也未证伪：冻结保持并挂在卡上；候选与持仓阶段打断用户。用户可以解除冻结（`dismiss_freeze`，须理由），或由研究员登记为未量化风险。

### 9.6 即时对账与重算

观测入库后系统立即：

1. 更新绑定该指标的事实变量；
2. 对以该指标为假设、报告期等于检查点的逻辑做**假设对账**（超预期 / 兑现 / 容差 / 偏离 / 跌破）；
3. 对财务派生变量做**派生对账**；
4. 用最近若干期序列判定证伪规则、杀死条件与先行指标；
5. 定期报告到达时做**盈利质量检查**（`quality_checks`）；
6. 重算定价快照（含收益分解）与价值变动桥；
7. 推导状态（§9.8），更新护栏（§11.2）；
8. 生成卡事件，按 §9.11 处理。

复查汇总这些对账，不重新判定已由代码判定的数值作用。

### 9.7 作用判定（系统）

| 作用     | 判定                                                                                              |
| -------- | ------------------------------------------------------------------------------------------------- |
| 验证     | 观测落在该期路径的熊、牛区间内；或转换后 ΔV(中) 绝对值 < `effect_threshold`                       |
| 强化     | 观测越过牛档（有利方向）；或转换后 ΔV(中) ≥ +`effect_threshold`                                   |
| 动摇     | 观测低于熊档；先行指标未达；转换后 ΔV(中) ≤ −`effect_threshold`；开关切到"削弱"；登记为未量化风险 |
| 证伪     | 触发证伪规则；开关切到"破坏"                                                                      |
| 只改定价 | 只有估值层的事实变量变化（价格、rf、β、倍数历史）                                                 |

ΔV(中) 指该事件转换后 V_T(中) 相对变化前的变化率，其他变量不变。同时满足多条时：不利优先于有利；不利中取最严重者（证伪 > 动摇）；有利中取较弱者（验证 > 强化）。LLM 可以把作用判得更严，不能更轻。

### 9.8 状态推导

**假设状态**

| 状态 | 条件                                                                                   |
| ---- | -------------------------------------------------------------------------------------- |
| 证伪 | 触发证伪规则；或其驱动开关处于"破坏"                                                   |
| 存疑 | 最近一次对账低于熊档；先行指标连续 `leading_miss_limit` 次未达；或其驱动开关处于"削弱" |
| 成立 | 其余                                                                                   |

**经营状态**

| 经营状态     | 条件                                                                       |
| ------------ | -------------------------------------------------------------------------- |
| 证伪         | 任一杀死条件触发                                                           |
| 关键驱动存疑 | 任一关键驱动存疑；或关键驱动所在分支的财务派生变量低于该期熊档（派生偏离） |
| 成立         | 其余                                                                       |

**只展示、不改变允许动作**：非关键变量的存疑与派生偏离；事实漂移（事实更新与情景切换累计使 V_T(中) 下修 ≥ `drift_threshold`）；逻辑漂移（本逻辑周期内假设修订累计下修 ≥ `revision_drift_threshold`）。

### 9.9 价值变动桥

每次重算都生成价值变动桥：从上一个定价快照到这一个，逐项列出事实更新、情景切换、假设修订、未量化风险、时间推移、价格与 rf 各自对 V_T(中)、V₀(中)、买点价的贡献（按顺序替换计算，合计等于总变化）。

### 9.10 确信度

| 复查中的作用汇总       | 分值变化                           |
| ---------------------- | ---------------------------------- |
| 有强化，且无动摇、证伪 | +1                                 |
| 只有验证               | +0.5                               |
| 有动摇                 | −1                                 |
| 有证伪                 | 置为 −2；重写或新立的版本从 0 开始 |

≥ 2 为高，0 到 2 为中，< 0 为低。修订与滚动继承分值。确信度只用于仓位（§11.4）。

### 9.11 打断与注意力预算

| 事件                                                       | 观察                   | 候选 | 持仓 |
| ---------------------------------------------------------- | ---------------------- | ---- | ---- |
| 否决级事件（官方）                                         | 打断                   | 打断 | 打断 |
| 否决级线索                                                 | 挂卡（冻结）           | 打断 | 打断 |
| 价格穿越买点                                               | 打断                   | 打断 | 打断 |
| 价格穿越 V₀(牛)                                            | —                      | —    | 打断 |
| 杀死条件触发                                               | 挂卡                   | 打断 | 打断 |
| 关键驱动存疑                                               | 挂卡                   | 挂卡 | 打断 |
| 到期、倍数主导的兑现（待滚动）                             | 挂卡（研究员自行处理） | 挂卡 | 打断 |
| 不利方向异动未解释                                         | 挂卡                   | 打断 | 打断 |
| 盈利质量 L3                                                | 挂卡                   | 打断 | 打断 |
| 需要仲裁（§10.5）                                          | 挂卡（区间按分歧加宽） | 打断 | 打断 |
| 阶段兑现、暂定作用低于阈值的信息、数据缺失、标签变化、其余 | 挂卡                   | 挂卡 | 挂卡 |

- **挂卡**：事件记在卡上，下一次由事件触发的复查（或用户打开卡）时一并处理；观察阶段的复查由研究员自行完成。
- **注意力预算**：每周用时目标 `attention_budget_hours`，每周打断上限 `interrupt_budget`（否决级不计）。超出时，候选卡的打断收缩为否决级、杀死条件、价格穿越三类，并在应用内提示预算使用情况。

### 9.12 价格监控与异动

- 盘中按 `price_poll_interval` 轮询覆盖卡现价：穿越买点价、V₀(牛) 时重算并按 §9.11 处理。
- 异动：单日相对沪深300 偏离超过 `anomaly_daily`，或 10 日累计超过 `anomaly_10d`。
- 不利方向异动：事件分析检索原因。找到原因则作为信息条目进入流水线；找不到则冻结建仓、加仓（H7），候选与持仓阶段打断用户，用户可解除（`dismiss_freeze`）。有利方向异动只挂卡。

## 11. 决策

### 11.1 允许的动作

| 经营         | 定价   | 无持仓                 | 有持仓                               |
| ------------ | ------ | ---------------------- | ------------------------------------ |
| 成立         | 低估   | 建、等待               | 加、持有、减                         |
| 成立         | 合理   | 等待（建需 override）  | 持有、减（加需 override）            |
| 成立         | 高估   | 等待                   | 减、清、持有（需理由）               |
| 成立         | 待滚动 | 等待；先确认滚动或结束 | 按滚动结果：滚动则持有，结束则减或清 |
| 任意         | 过期   | 等待                   | 持有、减、清                         |
| 关键驱动存疑 | 任意   | 等待                   | 持有、减、清                         |
| 证伪         | 任意   | 等待；重写或放弃       | 减、清（默认清）                     |

| 错误码                       | 规则                                         |
| ---------------------------- | -------------------------------------------- |

### 11.4 建议仓位

```
depth_scale = clamp(0.5 + clamp((买点价 − P) ÷ 买点价, 0, 1) ÷ depth_full, 0.5, 1)
width       = (V_T(牛) − V_T(熊)) ÷ V_T(中)

建议仓位 = min( single_cap,
               single_loss_budget ÷ max(|R(熊)|, 0.05),
               risk_budget × conv_factor[确信度] × depth_scale × clamp(1 − u_width × width, 0, 1),
               20 日日均成交额 × liquidity_ratio ÷ 卫星仓资金,
               剩余卫星仓预算, 剩余行业预算, 剩余主题预算 )
```

`single_loss_budget ÷ |R(熊)|` 使单票在熊市情景下对卫星仓造成的损失不超过 `single_loss_budget`。仓位中"未验证比例""时间"等不确定性分项待检验。

| 信号      | 触发                                     | 建议                                                                     |
| --------- | ---------------------------------------- | ------------------------------------------------------------------------ |
| S0 否决   | 否决级事件                               | 减仓或清仓，置顶                                                         |
| S1 证伪   | 杀死条件触发                             | 清仓                                                                     |
| S2 高估   | P ≥ V₀(牛)                               | 减至 × `take_profit_keep`；P ≥ V₀(牛) × (1 + `take_profit_extra`) 时清仓 |
| S3 结束   | 滚动后预期回报低于持有门槛（§8.5）       | 减仓或清仓                                                               |
| S4 未兑现 | 收敛窗口到期未兑现（按 §6.3 的计数条件） | 复查；达到滚动上限时减半                                                 |

### 11.6 决策包

建、加、减、清的决策包由系统组装，包含：

1. 结论与建议仓位（含各项上限）；
2. 研究员的推理链（每一步引用事实，推断单独标出）；
3. 一页纸六项（市场隐含、我方看法、收益来源、熊市情景、杀死条件、价格）；
4. 关键不确定性与"什么会改变结论"；
5. 反方意见与研究员回应；三视角估计与分歧度；
6. 护栏检查结果；允许动作；
7. LLM 的置信度，以及研究员在同类变量与行业上的历史区间覆盖率与偏差；
8. 自上次决策以来的价值变动桥。

用户可以确认、修改数量、拒绝，或通过助手追问。

### 11.7 override

只有用户能发起（`request_override`），只能放宽定价维度（合理价位的建、加）及 H5 中的行业、主题预算；须写理由；触发冷静期（H8）；冷静期内可取消；进入归因的过程审计。

## 12. 归因与学习

### 12.1 收益来源归因

**何时**：检查点披露、到期、兑现、证伪、清仓（事件驱动，不按日历）。

**算什么**：

1. 把从 t₀（逻辑层）或决策时点（决策层）至今的实际收益，按 §6.1 同一口径分解为盈利、倍数、分红；
2. 与事前快照中的分解对比；
3. 判断关键驱动在已到期检查点是否兑现；
4. 给出结论：

| 归因结论       | 条件                                           |
| -------------- | ---------------------------------------------- |
| 判断兑现       | 关键驱动兑现，收益主要来自事前的主要来源       |
| 逻辑对、定价错 | 关键驱动兑现，但被倍数收缩抵消，或价格没有跟上 |
| 运气           | 关键驱动没有兑现，收益来自其他来源             |
| 判断错误       | 关键驱动没有兑现，并且亏损                     |

**过程审计**（同时记录）：杀死条件是否被放宽（H3）、是否被遵守（触发后是否按建议处理）、事实是否被更正、仲裁与 override 的选择及事后结果。

LLM:复盘分析 写归因说明；出现"判断错误"、override 或与护栏冲突时请用户写一句复盘，可跳过。

### 12.2 岗位表现度量

| 岗位       | 指标               | 计算                                                       |
| ---------- | ------------------ | ---------------------------------------------------------- |
| 研究员     | 区间覆盖率         | 已披露检查点中，关键驱动实际值落在熊、牛区间内的比例       |
|            | 中档偏差           | 实际相对中档的平均偏差，按变量、行业、模板                 |
|            | 判断兑现率         | 归因结论为"判断兑现"或"逻辑对、定价错"的比例               |
|            | 收益来源一致率     | 实际正收益中来自事前主要来源的比例                         |
|            | 隐含预期判断命中率 | 兑现时实际值更接近我方中档、而非市场隐含值的比例           |
| 三视角估计 | 视角误差           | 每个视角中档与实际的偏差                                   |
| 事件分析   | 方向命中率         | 暂定判断方向与事后对账方向一致的比例                       |
| 反方       | 挑战应验率         | 挑战指出的风险事后发生（触发对应杀死条件或造成动摇）的比例 |
| 用户       | 仲裁与 override    | 仲裁选择与 override 的事后结果                             |

这些指标经 `get_role_performance` 喂回 LLM 的上下文（I4），并决定授权等级（§4.5）。

### 12.3 被拦机会与规则证据

护栏拦下建、加，或决策为等待时，系统记录假想仓位（按当时的建议仓位）；在之后的归因事件上计算其假想收益与分解，写入对应规则的证据（`rule_evidence`）：事后上涨为该规则的代价，事后下跌或大亏为该规则的收益。

### 12.4 经验库

LLM:复盘分析 把归因结论与跨卡发现写成经验条目（范围：卡 / 行业 / 模板 / 变量 / 全局；内容；来源归因；标签）。研究员与反方在立论、重写、挑战时按行业、模板、变量检索（`get_experiences`），并在判断的输入引用中记录考虑过哪些条目。经验条目不需要用户确认。

### 12.5 校准

某个变量 × 行业（或某条规则）的样本数达到 `calib_min_n` 时自动运行一次校准：路径覆盖率与偏差、派生对账覆盖率、关键驱动命中率、倍数规则的事后表现、交叉验证分歧、未量化风险的结局。产出的带宽系数、阈值、模板修改作为提议进入规则清单流程（§13.4）。

### 12.6 组合与用户层度量

组合相对基准与行业指数（`industry_benchmark`）的超额、最大回撤、大亏次数、用户每周用时与打断次数：滚动计算，随时可查，不触发动作。

## 13. 规则清单

### 13.1 字段

每条规则一行：编号、规则、防哪种错、收益渠道、代价、检验方法、状态、证据样本数、关联参数、版本。初版见附录 C。

### 13.2 状态与举证责任

| 状态   | 含义                                                |
| ------ | --------------------------------------------------- |
| 硬约束 | 阻断；必须有收益渠道与检验方法（`RULE_NO_CHANNEL`） |
| 警告   | 展示并记录，不阻断                                  |
| 待检验 | 默认关闭；回放或实盘证据达到要求后经批准启用        |
| 停用   | 证据表明无效或有害                                  |

### 13.3 证据来源

- **回放**：用机械规则生成代理逻辑作为固定输入（例如 g₁ 取近 3 年扣非 EPS 复合增速后截断、倍数按 §7.5），每次只开关一条规则，比较年化收益、最大回撤、交易次数、持仓时长。回放只检验机械规则，不检验 LLM 的判断（LLM 知道历史结果，存在前视偏差）。
- **实盘**：被拦机会的事后表现（§12.3）、岗位表现（§12.2）。

### 13.4 变更流程

提议（LLM:复盘分析 或校准，附证据）→ 能回放的先回放 → 用户批准（`approve_rule_change`）→ 规则清单、参数或模板生成新版本 → 生效。说不出收益渠道或证据不足的规则只能是警告。

**MetricDef**【判，用户】：`key`、`label`、`level`、`value_type`、`unit`、`direction`、`cadence`、`role`、`sanity`、`fetch_mapping`、`release_calendar`（预计披露日，供披露事件与数据缺失判定）。

**Observation**：`id`、`provenance`、`recorded_at`、`recorded_by`、`info_item_id`【系】；`subject_type`、`subject_id`、`metric_key`、`period_end`、`period_basis`、`disclosed_at`、`value` / `value_enum` / `value_text`、`structure`、`source`、`supersedes`【事】；`tier`（T1 数据接口 / T2 公开 JSON、白名单商业数据或两源确认的手录 / T3 其余手录）【算】。约束：`OBS_UNKNOWN_METRIC`、`OBS_SUBJECT_LEVEL_MISMATCH`、`OBS_SOURCE_UNTRUSTED`、`OBS_VALUE_INSANE`、`OBS_STRUCTURE_REQUIRED`、`OBS_FUTURE_DISCLOSURE`、`OBS_DUPLICATE_PERIOD`、`OBS_SUPERSEDES_MISMATCH`。取值函数 `valueAt`、`latestAt`、`seriesAt` 均接收 `at`，按 `disclosed_at ≤ at` 取修订链末端。

## 17. 闭合检查

`closure_report(card?)` 为只读领域函数。

| 环节     | 检查                                                                                  | 级别 |
| -------- | ------------------------------------------------------------------------------------- | ---- |
| 接入     | 每个启用信息源在其间隔 3 倍内至少成功一次；启动后已回补；事件分析积压未超过一天上限   | 告警 |
| 路由     | 每个粗筛命中的信息条目，都对所有命中的卡生成了卡事件                                  | 错误 |
| 披露     | 每个已过预计披露日加宽限期的检查点，要么已对账，要么有数据缺失事件与补取任务          | 错误 |
| 事实     | 快照引用的事实与 LLM 判断引用的事实，`disclosed_at` 不晚于快照或判断时间              | 错误 |
| 护栏     | 没有违反 H4–H9 的生效建、加决策（合规 override 除外）；没有未关联已生效决策的买入成交 | 错误 |
| 杀死条件 | 没有未判为重写的放宽                                                                  | 错误 |
| 授权     | 没有超出授权等级生效的变更                                                            | 错误 |
| 仲裁     | 没有带未仲裁条件的生效建、加决策                                                      | 错误 |
| 归因     | 每个归因事件都有归因记录                                                              | 告警 |
