## 0. 读法

**数据标记**

| 标记   | 含义                                                                       | 可变性                                 |
| ------ | -------------------------------------------------------------------------- | -------------------------------------- |
| 【事】 | 事实：外部世界已经发生、可观测的值（公告、数据、行情、政策原文、成交回报） | 只追加；修订用新记录加 `supersedes`    |
| 【线】 | 线索：未经官方来源证实的信息（媒体报道、快讯、传闻）                       | 只追加；可被证实或证伪                 |
| 【判】 | 判断：LLM 或用户写下的主张、假设、估计、解释、动作                         | 只能出新版本或新记录                   |
| 【算】 | 计算结果：系统由事实、线索和判断推出                                       | 不接受调用方传入；需要留历史时冻结快照 |
| 【系】 | 系统字段：id、版本号、时间戳                                               | 只由服务端生成                         |

**执行方**：系统（确定性代码）/ LLM:<岗位>（§4.3）/ 用户。文中数字凡标"示意"者只用于说明机制；参数名用代码字体，初始值见 §15。本文用内部术语；用户界面上的叫法见 §11.5。

## 1. 一句话模型

> **用户设定目标与边界，在平静时批准买入计划；LLM 研究公司、提出可证伪的估值逻辑、持续解读事件；系统把逻辑变成可计算的公式，按事件重算，在系统的建议上执行保护规则，并度量每个参与方的表现。目标是长期超额收益，一切管理机制都要说明它怎样服务于这个目标。**

```
               用户：边界 · 批准预案 · 确认交易 · 自主决策 · 仲裁 · 私有信息
                      ▲ 待办、提醒、决策包                 │
                      │                                    ▼
 事件 ──────▶  系统：事实 · 计算 · 状态 · 护栏 · 度量  ◀────▶  LLM：研究 · 估计 · 解读 · 对抗 · 归因
                      │
                      ▼
      逻辑（公式 + 关键驱动 + 杀死条件）→ 定价与仓位 → 预案 → 触发 → 成交 → 持有（批次复查、滚动）
                      │
      兑现、证伪、清仓 → 归因（事前与事后的收益分解；与基线比较）→ 岗位表现 → 规则
```

## 2. 目标、度量与范围

### 2.1 目标与度量

| 目标                         | 度量                                                                                                                        | 何时更新                       |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------- | ------------------------------ |
| **长期超额收益**（第一目标） | 卫星仓（个股 + 停放资产）相对沪深300 全收益的超额；另报**选股超额**：个股部分相对同期停放资产的超额                         | 滚动计算，随时可查，不触发动作 |
| 不出大亏                     | 单票亏损超过熊市底线的次数；卫星仓最大回撤                                                                                  | 发生即记录                     |
| 用户的时间                   | 用时、提醒次数（§9.10）                                                                                                     | 应用自动记录                   |
| 判断质量                     | 相对两条基线（市场隐含值、朴素外推）的技能分、熊档击穿率、事件判断方向命中率、挑战应验率（§12.2）；自主决策与系统建议的对比 | 每次归因事件后更新             |

### 2.2 停放资产

卫星仓中没有投向个股的资金默认持有 `parking_asset`（沪深300 ETF）：买入个股时从停放资产划出，卖出个股后回到停放资产（系统给出建议，用户执行并录入）。用户也可以选择只计量不持有（`parking_mode`），此时现金按停放资产的收益计量选股超额，但卫星仓的实际收益会承担现金拖累。

### 2.3 实现约束

服务于 §2.1 的目标，本身不是目标：逻辑可计算、可追溯每一步；事件可以落到变量的变化上；状态由代码推出；数据完整性与护栏遵守可由代码检查（§17）。

## 3. 设计原则

| #   | 原则                                                                                               |
| --- | -------------------------------------------------------------------------------------------------- |
| R1  | **管理对收益负责**：规则写明防哪种错、收益渠道、代价、检验方法；新规则先证明有用才成为硬约束       |
| R2  | **按能力分工，按证据授权**：系统做确定性的事，LLM 做需要推理的事，用户做设定与承诺                 |
| R3  | **护栏约束系统，透明约束用户**：系统不建议违反护栏的交易；用户自主决策时系统展示护栏结果并如实记录 |
| R4  | **严谨程度随资金敞口递增**：没有资金敞口时不做昂贵的推理                                           |
| R5  | **决策在平静时做**：重大判断前移到预案审阅，触发时刻只做执行                                       |
| R6  | **注意力是预算**：提醒少而准；同一报告期合并；不阻断的检查改为展示                                 |
| R7  | **收益来源由分析得出**：系统分解预期回报，随事件重算                                               |
| R8  | **事件驱动**：不设日历检查；预期事件没有发生本身是事件                                             |
| R9  | **按事件归因、与基线比较**：区分"逻辑对不对"和"收益好不好"；判断质量只算超出基线的部分             |

沿用的工程原则：LLM 提交判断、系统计算结果，断言引用事实；线索不是事实；价格只作用于定价；数值作用由代码判定，LLM 只能判得更严；先外部视角再内部视角；公式用受限表达式语言、语法树解释执行、禁止 `eval`。

## 4. 三方分工

### 4.1 分工原则

|          | 擅长                                                          | 不擅长                                               | 负责                                                             | 不做                                                         |
| -------- | ------------------------------------------------------------- | ---------------------------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------ |
| **系统** | 精确、一致、可复现、不知疲倦                                  | 理解、综合、判断                                     | 数据与出处、计算、状态、事件、护栏、记录、度量                   | 任何判断                                                     |
| **LLM**  | 读懂大量非结构化信息、跨领域综合、提出假说与反例、写推理链    | 算术；凭记忆陈述事实；迎合；过度自信；多实例错误相关 | 研究、建模判断、事件解读、预案与建议、对抗、归因解释、经验学习   | 产出计算结果、修改状态、绕过护栏、确认交易、陈述无出处的事实 |
| **用户** | 资金责任；风险偏好；私有信息与常识；判断该信任 LLM 到什么程度 | 时间和注意力有限；自身的行为偏差                     | 设定边界、批准预案、确认交易、自主决策、仲裁、补充信息、批准规则 | 写逻辑、维护模型、处理日常事件                               |

### 4.2 接口约定

| #   | 约定                                                           | 代码保证                                                             |
| --- | -------------------------------------------------------------- | -------------------------------------------------------------------- |
| I1  | LLM 提交判断（取值与区间、理由、引用、置信度），不提交计算结果 | 工具 schema 不含【算】【系】字段（`SCHEMA_DERIVED_FIELD_FORBIDDEN`） |
| I2  | 推理锚定事实；未引用的断言标为"推断"                           | 引用的事实存在且 `disclosed_at` 不晚于判断时间（`FACT_REF_INVALID`） |
| I3  | 判断写明"什么会改变我的看法"                                   | schema 必填；作为杀死条件的候选                                      |
| I4  | 系统把 LLM 的历史表现与经验库喂回 LLM                          | `get_role_performance`、`get_experiences`；输入引用记入 LlmJudgment  |
| I5  | 用户面对分层的决策包，而不是表单                               | §11.4                                                                |
| I6  | 每次 LLM 推理留痕                                              | LlmJudgment 关联 turn-trace 的 `trace_id`；用量计入费用视图          |

### 4.3 LLM 推理岗位

| 岗位       | agent                                            | 何时运行                       | 推理任务                                                                                                       | 系统校验与度量                                         |
| ---------- | ------------------------------------------------ | ------------------------------ | -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| 研究员     | `stock-research`（每张卡一个上下文）             | 立论、预案、复查、滚动、证伪   | 研究公司与行业；解读市场隐含预期；论点；关键驱动与区间、参照类；情景叙事；杀死条件；转换待转换条目；预案与建议 | 完备性、出处、覆盖；技能分、熊档击穿率、收益来源一致率 |
| 三视角估计 | `estimator`（以视角参数区分）                    | 预案；持仓重写；只针对关键驱动 | 自下而上、自上而下、外部视角各自独立估计 T 期中档                                                              | §5.6 区间规则；各视角误差                              |
| 事件分析   | `event-analyst`（接入服务内调用，无写工具）      | 信息到达；不利异动；线索       | 抽取；判断影响的变量、方向、幅度区间、是否已定价、可信度；检索异动原因与线索的官方来源                         | schema 校验；暂定 ΔV 由系统算；方向命中率              |
| 反方       | `short-thesis`（隔离上下文，可配置不同厂商模型） | 预案；持仓重写                 | 事前验尸；寻找反证；最强空头叙事；检查重写是否在移动球门                                                       | 必须引用研究员未用过的事实；挑战应验率                 |
| 复盘分析   | `review-analyst`                                 | 归因事件之后                   | 解释归因；跨卡寻找系统性偏差；起草规则、模板、参数修改；写经验库                                               | 提议走 §13                                             |
| 专项研究   | `industry-research`、`macro-research`            | 研究员委托                     | 行业、宏观的取数与分析                                                                                         | 无写命令                                               |
| 助手       | 对话入口                                         | 用户随时发起                   | 解释任何数字与判断；把用户的私有信息交给研究员                                                                 | 修改走同样校验                                         |

三视角估计的三个上下文互不可见，也看不到研究员的草案；反方必须引用研究员未用过的事实，可配置为另一厂商的模型。

### 4.4 用户的职责

1. **设定**：风险预算、注意力预算、停放资产、覆盖范围（`update_settings`）。
2. **批准预案、确认交易**：在预案阶段审阅并批准买入计划；对复查给出的减、清建议确认；在券商下单并录入成交。
3. **自主决策**：任何时候都可以自己决定买卖（`record_decision`）；系统展示决策包与护栏结果、提示 `cooldown_hours` 的冷静期，然后如实记录、单独归因，不拦截。
4. **仲裁**：只在分歧会改变结论时（§10.3）。
5. **补充**：私有信息与看法（`add_user_input`）；研究员据此修改逻辑时必须列出支持与反对证据（`USER_INPUT_NO_EVIDENCE`）。
6. **批准**：规则、模板、参数的变更；可随时否决一个逻辑。

### 4.5 授权

首期固定为 A0；按表现升级的 A1 放在 P4。交易永远由用户确认。

| 事项           | 观察     | 预案                     | 持仓               |
| -------------- | -------- | ------------------------ | ------------------ |
| 立论与修订     | LLM 生效 | LLM 生效，随预案审阅     | 用户确认（随复查） |
| 重写           | LLM 生效 | LLM 生效，已批准预案失效 | 用户确认           |
| 滚动或结束     | LLM 生效 | LLM 生效                 | 用户确认（随批次） |
| 建、加、减、清 | —        | 批准预案                 | 用户确认           |
| 持有、等待     | 自动记录 | 自动记录                 | 自动记录           |

越权提交被拒绝（`AUTONOMY_EXCEEDED`）。

### 4.6 LLM 可靠性机制

| 风险                 | 机制                                              |
| -------------------- | ------------------------------------------------- |
| 算错、编造事实       | 数字由系统计算；断言引用事实并核验                |
| 过度自信             | 三视角决定区间下限；区间得分与熊档击穿率反馈      |
| 事后合理化、移动球门 | 杀死条件不能放宽；反方检查重写                    |
| 多个实例错误相关     | 上下文隔离；反方必须用新事实；可换厂商模型        |
| 迎合用户             | 引用用户输入时必须列支持与反对证据                |
| 讲故事替代证据       | 收益来源由系统计算，与论点叙述并排展示            |
| 看法与市场共识趋同   | 技能分与市场隐含值、朴素外推两条基线比较（§12.2） |
| 前视偏差             | 回测只检验机械规则                                |

### 4.7 成本与等待

- 三视角估计与反方只在预案与持仓重写时运行；事件分析只处理路由到卡的条目，每日上限 `llm_daily_event_analyses`，超出按优先级排队（否决类 > 持仓卡 > 预案卡 > 观察卡）。
- 投研 agent 只暴露命令类工具，取数经服务端取数注册表；用 turn-trace 度量输入规模与耗时。
- 设置中显示按岗位、按卡的 LLM 费用。
- 立论与预案生成时分步显示进度与中间结果（市场隐含、关键驱动、三视角 2/3、反方……）。

## 5. 逻辑

### 5.1 定义

> **逻辑（Thesis）是一个以估值公式表达、可计算、可证伪的价值主张。** 在时间窗 [t₀, T] 内，资产价值由变量通过确定的公式算出；变量要么绑定事实，要么是带区间、理由和证伪条件的假设；主张是：按此公式，从现在持有到 T 的回报满足要求，且熊市情景的亏损在底线以内。

```
V_T(s) = F( 事实变量(t),  假设变量(s, 各期),  情景开关(s) )          s ∈ {熊, 中, 牛}
coe    = rf + β × ERP
V₀(s)  = ( V_T(s) + D(s) ) ÷ (1 + coe)^τ

主张：  ( V_T(中) + D ) ÷ P ≥ (1 + h)^τ        且        ( V_T(熊) + D ) ÷ P ≥ 1 − max_loss_floor
```

h 为有效回报门槛（§8.4），τ 为距 T 预计披露日的年数，D 为期间分红。**T 由逻辑所需证据的披露时点决定**：估值输入假设的最后一个检查点，按预计披露日到期，不早于下一个可披露报告期，不超过 `max_horizon_periods`（`HORIZON_INVALID`）。检查点是路径上的每一期，按预计披露日到期；倍数部分需要时另设收敛窗口。

**生命周期**：active（T 的观测尚未披露）→ due（已披露，滚动或结束尚未生效）→ superseded / completed / falsified / abandoned。

**版本类型**（系统比较新旧版本判定）：新立；修订（结构不变，只改路径数值、开关映射数值、倍数中档、收敛条件，且不放宽杀死条件）；重写（变量或公式增删改、开关增删、方法改变，或放宽任一杀死条件）；滚动（结构不变，T 后移）。

### 5.4 变量、口径与公式

**五层**：宏观（经济、政策、利率）、行业（规模、结构、价格、成本）、公司（经营驱动）、财务（**只能由公式推出**：营收、净利、扣非 EPS、ROE、BVPS、自由现金流、DPS 等，`RESULT_ASSUMED`）、估值（PE_T、PB_T、coe、V_T、V₀）。行业模板中毛利率、费用率也由公式推出；通用模型中它们是公司层驱动变量。

**类型**：事实变量（事实绑定，自动更新）、假设变量（各期熊中牛路径）、派生变量（公式）、情景开关（离散外部条件）、常量（引用事实或法规）、参数（RuleParams）。每个叶子变量必须是其中之一（`LEAF_UNBOUND`）。

**时间维度与口径**

- 每个变量声明频率（月 / 季 / 年）与口径（单期、年初至今累计、TTM、期末存量）；公式按期计算。
- 流量按期求和；比率由同口径分子、分母重算，不对比率取平均；存量取期末值。
- 年度变量的季度检查点按"年初至今累计"登记，与同口径观测对账；月度观测用于先行验证。
- 观测按变量口径换算后对账；换算所需期次缺失时生成数据缺失事件并自动补取；无法换算时拒绝绑定（`PERIOD_BASIS_MISMATCH`）。
- 存在未转股可转债、已披露增发预案或在实施的股权激励时，股本必须是假设（`DILUTION_UNMODELED`）。

**公式语言**：每个派生变量一条公式，附机制说明。允许数字、变量引用（可带期偏移）、`+ − × ÷ ^`、`min`、`max`、`clamp`、`sum`、`sw(开关, {状态: 值})`；解析为语法树解释执行。系统检查语法、引用、无环与量纲：单位由基本单位与数量级前缀（万、亿）组成，前缀在求值时换算；量纲不一致拒绝。以上任一不满足报 `FORMULA_INVALID`（附具体原因）；三个情景都须能算出 V_T（`VALUATION_NOT_COMPUTABLE`）。

### 5.6 三视角估计

预案阶段与持仓重写时，对每个关键驱动运行：

| 视角     | 依据                                       |
| -------- | ------------------------------------------ |
| 自下而上 | 公司数据：产能、订单、渠道、产品结构       |
| 自上而下 | 行业总量与结构、宏观约束、份额推算         |
| 外部视角 | 参照类：同类公司在类似规模或阶段的历史分布 |

- 三个上下文互不可见，也看不到研究员的草案；各自给出 T 期中档、理由与引用（`submit_estimate`）。缺失报 `ESTIMATES_REQUIRED`。
- **区间规则**：关键驱动在 T 的熊档不得优于三视角中最不利的估计，牛档不得劣于最有利的估计（`BAND_BELOW_ESTIMATES`）。
- 研究员中档落在三视角之外时须说明理由（展示，不阻断）。
- 分歧是否需要用户仲裁，按 §10.3 的"是否改变结论"判定。

### 5.7 情景与情景开关

| 情景     | 规则                                                                                                     |
| -------- | -------------------------------------------------------------------------------------------------------- |
| 中       | 所有假设取中档；开关取当前状态                                                                           |
| 熊       | 连贯的下行叙事；**至少包含 k − 1 个关键驱动的熊档**；熊市情景决定买点与仓位，是被度量最严的判断（§12.2） |
| 牛       | 连贯的上行叙事；定性优势在这里与长期增长段中表达                                                         |
| 压力测试 | 关键驱动同时取熊档、开关取最坏状态；只展示                                                               |

**情景开关**（可选，≤ 2 个）表示无法用连续数值表达的外部条件（例如购置税减免：延续 / 减半 / 取消）。每个状态写下严重度（基准 / 削弱 / 破坏）与对假设的映射，至少一个"破坏"状态。开关或情景不合法报 `SCENARIO_INVALID`。

### 5.8 杀死条件与收敛条件

杀死条件是立论时写下、提交后不能放宽的证伪规则：关键驱动的证伪规则、长期增长段的证伪规则（§7.5）、倍数部分"收敛条件连续 `max_rolls_without_convergence` 个窗口未兑现"、反方已采纳挑战对应的条件。

- **覆盖**：收益分解中占比 ≥ `component_major_share` 的每个正向部分至少一条杀死条件；倍数部分占比达到该阈值时必须写收敛条件（催化事件、关联变量、时间窗）；已采纳的挑战必须被覆盖。任一不满足报 `KILL_COVERAGE_MISSING`。
- **数量**：观察阶段 2–3 条；预案与持仓阶段不超过 `kill_max` 条。
- **不可放宽**：放宽阈值、延长连续期数、删除杀死条件，版本类型一律判为重写，确信度归零，并计入过程审计。

## 6. 收益来源

### 6.1 分解

```
EPS₀ = 当前扣非 EPS（TTM）；PE₀ = P ÷ EPS₀
g_E  = EPS_T ÷ EPS₀ − 1              周期股用 EPS_norm
g_M  = PE_T(中) ÷ PE₀ − 1
d    = D ÷ P
1 + R(中) = (1 + g_E) × (1 + g_M) + d

对数贡献（可直接相加）：c_E = ln(1 + g_E)；c_M = ln(1 + g_M)；c_D = ln(1 + R(中)) − c_E − c_M
占比 = 某正向部分的贡献 ÷ 全部正向贡献之和；负向部分为拖累项
```

其他方法同口径：PB-ROE 为 BVPS 增长、PB 变化、分红；PS 为营收增长、PS 变化。每次定价重算都从**当前价格**重新分解，写入定价快照。

### 6.2 展示

展示最大的正向部分及各部分占比；最大部分占比 < `component_primary_share` 时显示"混合"。论点叙述与计算出的来源并排展示，不一致时研究员须在逻辑中解释。主要来源发生变化（例如倍数修复完成后变为盈利增长）作为事件挂到卡上。

### 6.3 由计算驱动的行为

| 行为                 | 规则                                                                                                                  |
| -------------------- | --------------------------------------------------------------------------------------------------------------------- |
| 杀死条件与收敛条件   | 占比 ≥ `component_major_share` 的正向部分须被覆盖（§5.8）                                                             |
| 滚动还是结束         | 到期事件、或倍数主导的兑现事件发生时，按 §8.6 计算滚动后预期回报决定默认动作                                          |
| 滚动上限计数         | 只在"关键驱动在 T 未兑现"或"倍数部分占比 ≥ `component_primary_share`"时计数；关键驱动已兑现、只是价格滞后的滚动不计数 |
| 长期增长段必须可证伪 | 盈利部分占比 ≥ `component_primary_share` 时（§7.5）                                                                   |

## 7. 估值方法

### 7.1 默认方法：前瞻 PE

`V_T = 扣非 EPS_T × PE_T`。EPS 由经营模型推导到 T 所在的会计年度，不允许直接假设。

### 7.2 标的画像

| 维度     | 取值                                                                 | 判定                                                                                          |
| -------- | -------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| 行业组   | 金融-银行 / 金融-券商 / 金融-保险 / 周期 / 资源 / 地产 / 公用 / 一般 | 系统：行业分类映射                                                                            |
| 盈利状态 | 稳定盈利 / 亏损或微利 / 周期性                                       | 系统：TTM 扣非净利 ≤ 0 为亏损；近 5 年扣非净利变异系数 > `cyclical_cv` 或属周期行业组为周期性 |
| 分红特征 | 高股息 / 一般                                                        | 系统：近 3 年平均分红率 ≥ 50% 且股息率 ≥ 4%                                                   |
| 业务结构 | 单一 / 多元                                                          | 系统：最大分部收入占比 < 60% 且分部数 ≥ 2 为多元                                              |
| 价值来源 | 经营 / 资产重估 / 管线                                               | LLM:研究员 判断，系统校验不冲突                                                               |

画像随资格评估生成，年报披露事件后重新评估；画像变化导致主方法变化时须重写。

### 7.3 画像 → 方法

| 画像（按顺序匹配）               | 主方法              | 交叉验证                                                 | 本期   |
| -------------------------------- | ------------------- | -------------------------------------------------------- | ------ |
| 金融-保险                        | P/EV                | PB                                                       | 不支持 |
| 金融-银行、金融-券商             | PB-ROE              | 股息率                                                   | 支持   |
| 资源、地产，或价值来源为资产重估 | NAV                 | PB                                                       | 不支持 |
| 价值来源为管线                   | rNPV                | PS                                                       | 不支持 |
| 多元                             | SOTP                | PE                                                       | 不支持 |
| 亏损或微利                       | PS + 盈利路径       | 远期 PE 折现                                             | 支持   |
| 周期性                           | 正常化盈利 PE       | PB                                                       | 支持   |
| 其余（稳定盈利）                 | **前瞻 PE（默认）** | 高股息用股息率；模板含现金流模块时用 DCF；其余用反向 DCF | 支持   |

不支持的画像可以建卡、接收信息，但不能提交逻辑（`METHOD_INVALID`）。

### 7.4 方法估值模板

| 方法                 | 估值层公式                                                                                                                              |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 前瞻 PE              | `V_T = EPS_T × PE_T`                                                                                                                    |
| PB-ROE               | `BVPS_T = BVPS₀ + Σ EPS − Σ DPS`；`V_T = BVPS_T × PB_T`；推出值 `PB = (ROE_T − g) ÷ (coe − g)`                                          |
| 正常化盈利 PE        | `EPS_norm = BVPS_T × ROE_norm`（周期平均 ROE，假设）；`V_T = EPS_norm × PE_norm`                                                        |
| PS + 盈利路径        | `V_T = 营收_T × PS_T`；同时给出盈亏平衡期、目标净利率、目标年份 Y；交叉验证 `营收_Y × 目标净利率 ÷ N × PE_Y ÷ (1 + coe)^(Y − T)`        |
| DCF（交叉验证）      | 企业价值 = Σ FCFF 折现 + 终值；股权价值 = 企业价值 − 净负债（需模板含现金流模块）                                                       |
| 反向 DCF（交叉验证） | `g_implied = (P × (1 + coe)^n ÷ (EPS₀ × PE_exit))^(1/n) − 1`，PE_exit 取 §7.5 中档，n 为长期增长段年数；与 g₁ 比较（复用 `reverseDcf`） |
| 股息率（交叉验证）   | `V = DPS_{T+1} ÷ (coe − g)`，g ≤ `g_terminal_cap`                                                                                       |

### 7.5 倍数来源

| 步骤                 | 规则                                                                                                                                                                                                                                                     |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ① 相对历史分位定区间 | 标的扣非 TTM PE ÷ 基准 PE（`relative_multiple_benchmark`），取 `multiple_history_years` 年分位，再乘以当前基准 PE 折回。熊 = `p_bear` 分位，牛 = `p_bull` 分位，中档候选区间为 `[p_center_lo, p_center_hi]` 分位                                         |
| ② 基本面推出值       | 两段式 `PE_T = Σ_{i=1..n} 分红率₁ × x^i + 分红率₂ × (1 + g₁)^n × (1 + g₂) ÷ ((coe − g₂) × (1 + coe)^n)`，`x = (1 + g₁) ÷ (1 + coe)`；PB 用 `(ROE − g) ÷ (coe − g)`。`g₂ ≤ g_terminal_cap`，`coe − g₂ ≥ min_spread`；按 g₁ 的熊中牛得 J(熊)、J(中)、J(牛) |
| ③ 中档               | 须在 ① 的候选区间内或在 J(中) × (1 ± `justified_tolerance`) 内，否则拒绝（`MULTIPLE_INVALID`）；只满足一个时须说明                                                                                                                                       |
| ④ 熊档               | 取 ① 的 `p_bear` 分位与 J(熊) 的较低者                                                                                                                                                                                                                   |
| ⑤ 增速换挡           | 画像变化，或 g₁(中) 与近年实际增速相差超过 `regime_shift_gap` 时，① 只作参照，中档以 J(中) 为准                                                                                                                                                          |
| 历史不足             | 不足 `multiple_min_years` 年：熊 = 中 × `fallback_bear_factor`                                                                                                                                                                                           |

**长期增长段是可证伪的假设**：g₁、n、分红率₁ 有锚（近 3 至 5 年实际复合增速）、至少一个先行指标、作用于滚动复合增速的证伪规则；它们经推出值进入倍数与 V，参与敏感度排序，可以成为关键驱动。推出值使利率进入倍数，是宏观作用于估值的定量通道。

### 7.6 交叉验证

价值口径分歧 = 主方法与交叉验证的 V_T(中) 之差 ÷ 主方法 V_T(中)，超过 `cross_check_divergence` 时研究员须说明；反向 DCF 按增速比较，g₁(中) − g_implied 超过 `implied_growth_gap` 时须说明。分歧计入门槛的加成待检验，默认关闭。

### 7.7 行业经营模板

| 行业 | 方法                      | 核心骨架                                                                                     | 推荐的开关主题                       |
| ---- | ------------------------- | -------------------------------------------------------------------------------------------- | ------------------------------------ |
| 整车 | PE                        | 总量 × 渗透率 × 份额 + 海外 → 销量；均价 × 传导 → 单价；原材料 → 成本；毛利率、费用率 → 净利 | 购置税政策、价格战、海外贸易壁垒     |
| 白酒 | PE                        | 销量 × 吨价 → 营收；毛利率、税金率、费用率 → 净利；批价与渠道库存为先行指标                  | 消费税改革、渠道价格体系             |
| 家电 | PE                        | 内销量 + 外销量 → 销量；均价、原材料 → 毛利率；费用率 → 净利                                 | 以旧换新补贴、原材料价格、出口与汇率 |
| 银行 | PB-ROE                    | 贷款增速、净息差、非息收入、成本收入比、信用成本 → 净利 → ROE、BVPS；分红率 → DPS            | 利率调整、地产风险、地方债务         |
| 煤炭 | 正常化 PE，交叉验证股息率 | 产量 × 煤价 → 营收；单位成本 → 利润；周期平均 ROE → 正常化 EPS；分红率 → DPS                 | 产能与安监政策、进口煤、长协价格机制 |

首期只实现整车模板与通用模型，其余随 P1b。模板版本化，修改走规则清单流程。

## 8. 定价与仓位

### 8.1 V_T

三个情景的取值代入公式，按期计算到 T，得到 V_T(熊)、V_T(中)、V_T(牛) 与每一步的中间值（完整保留，供展示）。

### 8.2 资本成本、分红与 V₀

```
rf  = 10 年期国债收益率最新观测
β   = 对沪深300 的周收益回归（beta_window_weeks），Blume 调整 0.67β + 0.33；数据不足取 1
coe = rf + β × ERP
D   = 现在到 T 的预期分红（由 DPS 推出；没有 DPS 时取最近一期每股分红 × 期间年数）
τ   = 现在到 T 预计披露日的年数
V₀  = (V_T + D) ÷ (1 + coe)^τ
```

### 8.3 预期回报

```
R(中) = (V_T(中) + D) ÷ P − 1      年化：(1 + R)^(1/τ) − 1（τ < 0.25 时按 0.25 处理）
R(熊) = (V_T(熊) + D) ÷ P − 1
```

### 8.4 有效门槛与买点

```
width = (V_T(牛) − V_T(熊)) ÷ V_T(中)
h     = hurdle_base + premium_grade[资格等级] + p_width × width + Σ 未量化风险加成      上限 hurdle_cap

买点价 = min( (V_T(中) + D) ÷ (1 + h)^τ ,  (V_T(熊) + D) ÷ (1 − max_loss_floor) )
```

未量化风险只用于无法建模的负面事件（例如未决诉讼），按严重度取 `unquantified_premium`。其他门槛加成项在规则清单中待检验，默认关闭。

### 8.5 建议仓位

```
depth_scale = clamp(0.5 + clamp((买点价 − P) ÷ 买点价, 0, 1) ÷ depth_full, 0.5, 1)

建议仓位 = min( single_cap,
               single_loss_budget ÷ max(|R(熊)|, 0.05),
               risk_budget × conv_factor[确信度] × depth_scale,
               20 日日均成交额 × liquidity_ratio ÷ 卫星仓资金,
               剩余卫星仓预算, 剩余行业预算, 剩余主题预算 )
```

熊市底线 `max_loss_floor` 只是硬边界；底线以内，熊市越深，熊市损失预算项越小，仓位随之连续变小。五问与决策包展示的仓位与熊市亏损，都按**买点价位**计算，并标出哪一项最紧。

### 8.6 停放资产与持有门槛

```
停放资产预期回报 = rf + ERP（β = 1）
hold_hurdle     = 停放资产预期回报 + hold_friction
```

到期事件（T 的观测披露），或倍数主导的兑现事件（倍数部分占比 ≥ `component_primary_share` 且价格收敛到 V₀(中) 的 `convergence_tol` 以内，或收敛条件中的催化事件发生）发生时：

```
滚动草案：T' = T 之后的下一个检查点；结构不变，下一期路径由研究员补充
R_roll  = (V_T'(中) + D') ÷ P − 1，τ' = 现在到 T' 预计披露日的年数
默认动作：1 + R_roll ≥ (1 + hold_hurdle)^τ' → 滚动并持有；否则 → 结束（有持仓时减或清，资金回到停放资产）
```

达到滚动上限（§6.3 的计数条件）后不能再滚动（`ROLL_LIMIT_REACHED`），倍数部分的杀死条件触发。

### 8.7 市场隐含值与预期差

对每个关键驱动：其他变量取中档，二分求解使 V₀(中) = P 的值。分别在当前倍数与我方倍数下求解，两者都展示；预期差以当前倍数下的隐含值为准。不单调或无解时记为"无法反解"。市场隐含值同时是判断质量的基线之一（§12.2）。

### 8.8 敏感度与关键驱动

对每个假设、长期增长段和倍数：其他取中档，该变量分别取熊档和牛档，计算 V_T(中) 的变化幅度并排序；假设与长期增长段中的前 `key_top_k` 个自动成为关键驱动，倍数只展示。

### 8.9 路径带宽下限

```
sigma = 该指标最近 band_history_periods 期相邻变化的标准差
每个检查点最小带宽 = band_min_k × sigma × sqrt(该检查点距锚的期数)
```

历史不足 `band_min_history` 期时跳过；预案与持仓重写时，关键驱动在 T 的区间同时须覆盖三视角（§5.6）。

### 8.10 定价状态与价格信号

| 状态   | 条件（按顺序）                                                  |
| ------ | --------------------------------------------------------------- |
| 过期   | 关键驱动的检查点数据缺失超过 `disclosure_grace_days` 且补取未果 |
| 待滚动 | 到期或倍数主导的兑现之后，滚动或结束尚未生效                    |
| 高估   | P ≥ V₀(牛)                                                      |
| 低估   | P ≤ 买点价                                                      |
| 合理   | 其余                                                            |

**熊档击穿**：P < V₀(熊) 时生成事件——市场的定价已经差于我们的熊市情景，要求研究员解释是熊市情景过于乐观，还是市场过度悲观。

**买点触发频率**（只展示）：过去 `multiple_history_years` 年中，扣非 TTM PE 低于"买点价 ÷ 当前扣非 EPS"的交易日占比，让用户对多久会触发有预期。

### 9.3 接入流水线

```
拉取 → 原始信息
  → ① 去重（URL、内容哈希、近似哈希）
  → ② 粗筛（系统）：标的、行业、主题、指标名的字典匹配；未命中只存档
  → ③ 事件分析（LLM，仅命中条目）：摘要、事件类型、涉及对象、候选数值；对每张命中的卡给出暂定判断
  → ④ 生成事实：official → 事件与观测；commercial → 观测（T2）；media → 线索
  → ⑤ 即时对账与重算（§9.5）
  → ⑥ 生成卡事件，按 §9.10 提醒或挂卡；冻结按 H7
```

事件分析没有写入工具，输出经 schema 校验后由系统写入；只能增加标签，不能决定作用或提醒。**暂定判断** `{变量, 方向, 幅度区间, 是否已定价, 可信度}`：系统按幅度区间中点算出暂定 ΔV(中)，只用于提醒与累计判断，不改变定价快照；正式变化在复查中由研究员转换后生效。对已由代码判定作用的对账，暂定判断只能更严（`EFFECT_CONFLICTS_COMPUTED`）。

### 9.4 线索

否决级线索（如"传立案调查"）冻结系统的建仓、加仓建议（H7），事件分析同时检索官方来源：找到则按官方条目处理；核实为不实则解除冻结；既未证实也未证伪则冻结保持并挂卡，预案与持仓阶段提醒用户，用户可以解除冻结，或由研究员登记为未量化风险。

### 9.5 即时对账与重算

观测入库后系统立即：更新绑定的事实变量 → 对检查点做假设对账与派生对账（超预期 / 兑现 / 容差 / 偏离 / 跌破）→ 判定证伪规则、杀死条件与先行指标 → 定期报告到达时做盈利质量检查（§11.1）→ 重算定价快照（含收益分解）与价值变动桥 → 推导状态 → 更新护栏与预案有效性 → 生成卡事件。复查汇总这些结果，不重新判定已由代码判定的数值作用。

### 9.6 作用判定

| 作用     | 判定                                                                                              |
| -------- | ------------------------------------------------------------------------------------------------- |
| 验证     | 观测在该期熊、牛区间内；或转换后 ΔV(中) 绝对值 < `effect_threshold`                               |
| 强化     | 观测越过牛档（有利方向）；或转换后 ΔV(中) ≥ +`effect_threshold`                                   |
| 动摇     | 观测低于熊档；先行指标未达；转换后 ΔV(中) ≤ −`effect_threshold`；开关切到"削弱"；登记为未量化风险 |
| 证伪     | 触发证伪规则；开关切到"破坏"                                                                      |
| 只改定价 | 只有估值层事实变化（价格、rf、β、倍数历史）                                                       |

同时满足多条时：不利优先于有利；不利中取最严重者；有利中取较弱者。

### 9.7 状态推导

| 假设状态 | 条件                                                                               |
| -------- | ---------------------------------------------------------------------------------- |
| 证伪     | 触发证伪规则；或其驱动开关处于"破坏"                                               |
| 存疑     | 最近一次对账低于熊档；先行指标连续 `leading_miss_limit` 次未达；或其驱动开关"削弱" |
| 成立     | 其余                                                                               |

| 经营状态     | 条件                                                           |
| ------------ | -------------------------------------------------------------- |
| 证伪         | 任一杀死条件触发                                               |
| 关键驱动存疑 | 任一关键驱动存疑；或关键驱动所在分支的财务派生变量低于该期熊档 |
| 成立         | 其余                                                           |

只展示、不改变允许动作：非关键变量的存疑、事实漂移（累计下修 ≥ `drift_threshold`）、逻辑漂移（本周期假设修订累计下修 ≥ `revision_drift_threshold`）。

### 9.8 价值变动桥与确信度

每次重算生成价值变动桥：从上一个快照到这一个，逐项列出事实更新、情景切换、假设修订、未量化风险、时间推移、价格与 rf 对 V_T(中)、V₀(中)、买点价的贡献，合计等于总变化。

确信度只用于仓位：复查中有强化且无动摇、证伪 +1；只有验证 +0.5；有动摇 −1；有证伪置为 −2，重写或新立从 0 开始。≥ 2 为高，0 到 2 为中，< 0 为低。

### 9.9 披露批次

同一报告期（例如 2026 年报）的持仓卡披露合并为一个批次：

1. 第一张持仓卡的该期披露到达时开批，列出所有持仓卡该期的预计披露日；
2. 每份披露到达时照常即时对账、重算，结果挂进批次；
3. 所有预期披露到齐，或最后一个预计披露日加 `disclosure_grace_days` 后，批次完成；
4. 批次中有需要用户确认的事项（滚动或结束、关键驱动存疑、盈利质量 L3、研究员的减仓建议）时**提醒一次**，进入批量复查；全部兑现时只生成摘要挂入待办。

杀死条件触发、否决级事件、熊档击穿不进批次，立即提醒。观察与预案阶段的卡不进批次，由研究员各自处理。

### 9.10 提醒与注意力预算

| 事件                                                     | 观察                         | 预案                 | 持仓             |
| -------------------------------------------------------- | ---------------------------- | -------------------- | ---------------- |
| 否决级事件（官方）或否决级线索                           | 挂卡（线索冻结）             | 提醒                 | 提醒             |
| 杀死条件触发                                             | 挂卡                         | 提醒                 | 提醒             |
| 熊档击穿                                                 | 挂卡                         | 提醒                 | 提醒             |
| 预案触发（价格到计划价且预案有效）                       | —                            | 提醒（只需录入成交） | 提醒（加仓预案） |
| 价格 ≥ V₀(牛)                                            | —                            | —                    | 提醒             |
| 不利方向异动未解释                                       | 挂卡                         | 提醒                 | 提醒             |
| 披露批次完成且有待确认事项                               | —                            | —                    | 提醒（每批一次） |
| 进入预案阶段（预案待审阅）、预案失效                     | 待办（价格已低于买点时提醒） | 待办                 | 待办             |
| 其余（阶段兑现、暂定作用低于阈值、数据缺失、来源变化等） | 挂卡                         | 挂卡                 | 挂卡或并入批次   |

- **挂卡**：记在卡上，在下一次由事件触发的复查或用户打开卡时处理；观察阶段由研究员自行复查。
- **待办**：不推送通知，在应用内待办列表中等待用户处理。
- **注意力预算**：每周用时目标 `attention_budget_hours`，每周提醒上限 `interrupt_budget`（否决级不计）。超出时，预案卡的提醒收缩为否决级、杀死条件、预案触发三类，并在应用内显示预算使用情况。

### 9.11 价格监控与异动

盘中按 `price_poll_interval` 轮询覆盖卡与停放资产的现价。异动：单日相对沪深300 偏离超过 `anomaly_daily`，或 10 日累计超过 `anomaly_10d`。不利方向异动由事件分析检索原因：找到原因则作为信息条目进入流水线；找不到则冻结系统的建仓、加仓建议（H7），预案与持仓阶段提醒用户，用户可解除。有利方向异动只挂卡。

## 11. 护栏、动作与决策包

### 11.1 护栏

护栏约束**系统给出的建议**（预案、复查建议）。用户的自主决策不被拦截，但决策包会展示护栏结果，并单独归因。

| #   | 护栏                                                                                                             | 拒绝码                                                                                      |
| --- | ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| H1  | 数据正确：事实带出处、`disclosed_at` 不晚于使用时点；口径、量纲、股本稀释正确；成交在当日涨跌停区间内、T+1、可卖 | `OBS_*`、`FACT_REF_INVALID`、`PERIOD_BASIS_MISMATCH`、`DILUTION_UNMODELED`、`TRADE_INVALID` |
| H2  | 所有数字由系统计算，LLM 只提交判断                                                                               | `SCHEMA_DERIVED_FIELD_FORBIDDEN`                                                            |
| H3  | 杀死条件不能放宽；放宽即判为重写，确信度归零                                                                     | 系统自动改判版本类型                                                                        |
| H4  | 熊市底线：只在 R(熊) ≥ −`max_loss_floor` 时建议建、加                                                            | `GUARDRAIL_BLOCKED`                                                                         |
| H5  | 仓位上限：单票、行业、主题（按卡的行业与主题标签计算）、熊市损失预算、流动性                                     | `GUARDRAIL_BLOCKED`                                                                         |
| H6  | 资格不通过或盈利质量 L3 时，不建议建、加                                                                         | `GUARDRAIL_BLOCKED`                                                                         |
| H7  | 冻结：否决级事件或线索、杀死条件触发、关键驱动存疑、不利异动未解释、定价过期时，不建议建、加                     | `GUARDRAIL_BLOCKED`                                                                         |

**盈利质量检查**（`quality_checks`，复用 `RED_FLAG_THRESHOLDS`）：经营现金流 ÷ 净利、应收与存货增速相对营收增速、商誉 ÷ 净资产、有息负债 ÷ 总资产、存贷双高。单项触发为 L2（挂卡）；两项及以上，或经营现金流 ÷ 净利连续两期低于阈值，为 L3。

**决策流程校验**：交易类决策须经用户确认或来自已批准的有效预案（`USER_CONFIRMATION_REQUIRED`、`PLAN_INVALIDATED`）；预案须有针对当前版本的反方挑战（`CHALLENGE_REQUIRED`），挑战须引用研究员未用过的事实（`CHALLENGE_NO_NEW_EVIDENCE`）；需要仲裁的预案未经仲裁不能批准（`ARBITRATION_REQUIRED`）；LLM 只能生效授权范围内的变更（`AUTONOMY_EXCEEDED`）；系统建议的动作须在允许范围内（`ACTION_NOT_ALLOWED`）。

### 11.2 允许的动作（系统建议）

| 经营         | 定价   | 无持仓             | 有持仓                               |
| ------------ | ------ | ------------------ | ------------------------------------ |
| 成立         | 低估   | 建（按预案）、等待 | 加（按预案）、持有、减               |
| 成立         | 合理   | 等待               | 持有、减                             |
| 成立         | 高估   | 等待               | 减、清、持有（需理由）               |

## 12. 归因与学习

### 12.1 收益来源归因

**何时**：检查点披露、到期、兑现、证伪、清仓。

**算什么**：把从 t₀（逻辑层）或决策时点（决策层）至今的实际收益按 §6.1 同一口径分解，与事前分解对比，判断关键驱动是否兑现，给出结论：

| 结论           | 条件                                           |
| -------------- | ---------------------------------------------- |
| 判断兑现       | 关键驱动兑现，收益主要来自事前的主要来源       |
| 逻辑对、定价错 | 关键驱动兑现，但被倍数收缩抵消，或价格没有跟上 |
| 运气           | 关键驱动没有兑现，收益来自其他来源             |
| 判断错误       | 关键驱动没有兑现，并且亏损                     |

**过程审计**：杀死条件是否被放宽、触发后是否按建议处理；事实是否被更正；仲裁选择及事后结果；**自主决策与系统建议各自的结果**。

LLM:复盘分析 写归因说明；出现"判断错误"或自主决策亏损超过熊市底线时，请用户写一句复盘，可跳过。

### 12.2 技能分与基线

对每个关键驱动在已披露检查点上的表现：

```
区间得分（越小越好）：S = (u − l) + (2 ÷ α) × (l − y)⁺ + (2 ÷ α) × (y − u)⁺
  l、u 为熊、牛档（按方向），y 为实际值，α = 1 − nominal_coverage
中档技能分：skill = 1 − MAE(我方中档) ÷ MAE(基线)，大于 0 表示优于基线
基线一：市场隐含值（§8.7，立论时按当前倍数反解）
基线二：朴素外推（锚按近 3 年复合增速外推；区间按 §8.9 的带宽下限）
```

| 岗位       | 指标                                                                                                                   |
| ---------- | ---------------------------------------------------------------------------------------------------------------------- |
| 研究员     | 区间得分（相对朴素外推）；中档技能分（相对两条基线）；熊档击穿率（实际差于熊档的比例，目标约为 α ÷ 2）；收益来源一致率 |
| 三视角估计 | 各视角的中档误差                                                                                                       |
| 事件分析   | 暂定判断的方向命中率                                                                                                   |
| 反方       | 挑战应验率                                                                                                             |
| 用户       | 仲裁选择与自主决策的事后结果                                                                                           |

区间得分同时惩罚过宽与未覆盖，不能靠放宽区间刷高。指标经 `get_role_performance` 喂回 LLM 的上下文。

### 12.3 被拦机会与规则证据

护栏拦下系统的建仓、加仓建议，或决策为等待时，系统记录假想仓位；之后在归因事件上计算其假想收益，写入对应规则的证据：事后上涨为代价，事后下跌或大亏为收益。自主决策违反护栏时，其结果同样计入该护栏的证据。

### 12.4 经验库

LLM:复盘分析 把归因结论与跨卡发现写成经验条目（范围：卡 / 行业 / 模板 / 变量 / 全局）。研究员与反方在立论、预案、重写时按行业、模板、变量检索，并在输入引用中记录考虑了哪些条目。经验条目不需要用户确认。

### 12.5 校准

某个变量 × 行业（或某条规则）的样本数达到 `calib_min_n` 时，生成带宽系数、阈值、模板的修改提议，走规则清单流程（P4 起自动运行）。

## 13. 规则清单

**字段**：编号、规则、防哪种错、收益渠道、代价、检验方法、状态、证据样本数、关联参数、版本。初版见附录 B。

**状态**：硬约束（阻断；必须有收益渠道与检验方法，`RULE_NO_CHANNEL`）/ 待检验（默认关闭）/ 停用。不阻断的检查不登记为规则。

**证据**：回放——用机械规则生成的代理逻辑作为固定输入（例如 g₁ 取近 3 年扣非 EPS 复合增速截断，倍数按 §7.5），每次只开关一条规则，比较收益、回撤、交易次数、持仓时长；回放只检验机械规则，不检验 LLM 的判断。实盘——被拦机会、自主决策与岗位表现。

**变更**：提议（附证据）→ 能回放的先回放 → 用户批准 → 规则、参数或模板生成新版本 → 生效。

## 17. 闭合检查

`closure_report(card?)` 为只读领域函数。

| 环节     | 检查                                                                                | 级别 |
| -------- | ----------------------------------------------------------------------------------- | ---- |
| 接入     | 每个启用信息源在其间隔 3 倍内至少成功一次；启动后已回补；事件分析积压未超过一天上限 | 告警 |

| 披露     | 每个已过预计披露日加宽限期的检查点，要么已对账，要么有数据缺失事件与补取任务        | 错误 |

| 杀死条件 | 没有未判为重写的放宽                                                                | 错误 |
